# 待手动验证的项目

这些项目要用真实硬件、真实环境或真实操作才能测，自动测试覆盖不到。有条件时请按本表逐项验证，结果写在"结果"一列，发现问题记下现象和截图。

## 串口（P7 M1）

**需要的设备**：一块 USB 转串口的开发板，推荐 ESP32 DevKit（CP2102 或 CH340 芯片）；一根 USB 数据线；可选装 esptool（`pip install esptool`）。

**准备**：插上板子，在"新建连接 → 串口"里选设备、选波特率 115200，保存后打开。

| # | 项目 | 怎么测 | 预期 | 结果 |
|---|---|---|---|---|
| S1 | 设备识别 | 打开"串口设备"下拉 | 列出 `/dev/cu.usbserial-*` 或 `/dev/cu.wchusbserial-*`，带 USB 描述（如"Silicon Labs CP2102"）和 VID:PID；优先列出 `cu.*` 设备，`tty.*` 排在后面 | |
| S2 | 收发 | 打开端口，按板子上的 EN 复位键 | 看到启动日志，中文不乱码；在终端里输入能发给板子（比如 MicroPython 的 REPL） | |
| S3 | 不重开端口切换波特率 | 工具条"115200 · 8N1 ▾"切到 9600，再切回 | 提示"波特率已切换为 … · 无需重新打开端口"；切到 9600 后输出变成乱码，切回来恢复正常 | |
| S4 | 自定义串口参数 | 编辑器的"自定义 / 高级…"里改数据位、校验、停止位、流控 | 保存后重新打开，参数生效，且与板子的设置一致 | |
| S5 | DTR / RTS 方向 | 分别切换工具条上的 DTR、RTS | 原型默认 DTR 为开（绿色）。打开端口时板子不应被意外复位，也不应进入下载模式 | |
| S6 | 复位 EN | 点"复位 EN → 复位 EN" | 板子重启，重新打出启动日志 | |
| S7 | 下载模式 | 点"复位 EN → 下载模式" | 板子打出 `waiting for download`，即进入 ROM 下载模式 | |
| S8 | 让出端口给 esptool | 点"关闭端口"，再在本机终端运行 `esptool.py --port <设备> chip_id`；完成后点"打开端口" | 提示"端口已关闭 · 可以用 esptool 烧录固件了"；esptool 能连上板子；重新打开后能继续收发 | |
| S9 | 拔出与插回 | 会话开着时拔掉 USB，等 3 秒再插回同一个口 | 拔出后显示"设备已断开"，已有输出和日志保留；插回后约 1 秒内自动重新打开 | |
| S10 | 显示切换 | 依次打开 HEX、时间戳；切换"换行"为 CRLF / LF / CR | HEX 显示为偏移 + 十六进制 + ASCII；时间戳为 `[HH:MM:SS.mmm]`；换行切换后，发出的命令结尾随之变化 | |
| S11 | 原始数据不受显示影响 | 开着 HEX 或时间戳时录制或记日志 | 录制（.cast）和会话日志里是原始输出，不是 HEX 或带时间戳的文本 | |
| S12 | 测试连接 | 新建连接里点"测试连接" | 打开端口后立即关闭，提示成功；设备被占用或不存在时给出中文说明 | |

**注意**：USB 串口芯片的 DTR/RTS 通常是低电平有效。程序里按 esptool 的经典时序实现（见 `crates/shellmate-serial/src/sequence.rs`）。如果 S6/S7 的效果相反，说明这块板子的电路接法不同，请把板子型号记下来。

## 凭据库、Touch ID 与配置包（P7 M3）

**需要的条件**：带 Touch ID 的 Mac（或连着妙控键盘指纹版）；有几台已保存密码的主机；第二台 Mac 或第二个 macOS 用户（测配置包手动同步）。开发版每次重新编译后签名会变，macOS 读钥匙串时可能弹"允许访问"，点"始终允许"即可。

| # | 项目 | 怎么测 | 预期 | 结果 |
|---|---|---|---|---|
| V1 | 钥匙串 → 主密码库 | 设置 → 凭据与安全 → 选"主密码加密本地库"，设一个强度至少"中"的主密码 | 提示成功；"钥匙串访问"App 里搜 `Shellmate`，原有的 `host:…:password` 条目消失；重新连接这些主机不再问密码（需先解锁） | |
| V2 | 解锁与取消 | 退出重开 App，连接一台存了密码的主机 | 弹"解锁凭据库"；输错提示错误、不连接；点取消则这次连接取消并说明原因；输对后连上 | |
| V3 | Touch ID 启用 | 解锁状态下打开"用 Touch ID 解锁凭据" | 开关可用（没有指纹时置灰并说明原因）；"钥匙串访问"里出现 `Shellmate Vault Key` 条目 | |
| V4 | Touch ID 解锁 | 立即锁定（⌘K → 立即锁定凭据库），再连接主机，点"使用 Touch ID" | 弹系统指纹框，提示"解锁 Shellmate 凭据库"；按指纹后解锁并连接；在指纹框点取消则保持锁定 | |
| V5 | 改主密码后 Touch ID 仍可用 | 更改主密码（要先输入当前主密码），再锁定并用 Touch ID 解锁 | 当前主密码输错提示"当前主密码不正确"且不改；改完后 Touch ID 照常解锁，旧主密码不再能解锁 | |
| V6 | Touch ID 关闭 | 关掉 Touch ID 开关 | `Shellmate Vault Key` 条目被删除；之后解锁对话框没有 Touch ID 按钮 | |
| V7 | 闲置锁定 | 保持开关打开，开着一个 SSH 会话，15 分钟不碰 App（也可以合盖超过 15 分钟） | 提示"凭据库已闲置锁定"；已开的 SSH 会话不断；新的连接要重新解锁 | |
| V8 | 主密码库 → 钥匙串 | 选回"系统钥匙串" | 凭据回到钥匙串（"钥匙串访问"里重新出现），`Shellmate Vault Key` 被删；连接不需要解锁 | |
| V9 | 忘记主密码 | 解锁对话框点"忘记主密码？" → 重置凭据库 | 红字说明会永久丢失哪些凭据；确认后主机都还在，只有保存的密码 / 口令没了 | |
| V10 | 导出配置包 | 同步与备份 → 导出…，勾选全部内容，设导出口令 | 系统保存对话框默认名 `shellmate-YYYY-MM-DD.smbundle`；文件不是明文（用文本编辑器打开看不到主机名） | |
| V11 | 两台设备手动同步 | 在 A 导出 → B 导入；在 B 改一台主机地址、加一条快捷命令后导出 → A 导入 | B 首次导入全部为"新增"；A 导入时改过的主机显示"冲突"并有字段对比，新命令为"新增"，其余折叠为"相同 N 项"；选"覆盖"后 A 的主机被更新而不是多出一份 | |
| V12 | 冲突的三种选择 | 导入时对冲突项分别选跳过 / 覆盖 / 另存一份 | 跳过：本机不变；覆盖：本机改为文件中的内容；另存一份：多出一个名字带"（导入）"的副本，带上它的密码 | |
| V13 | 错误口令与损坏文件 | 导入时输错口令；或用十六进制编辑器改文件中间一个字节后导入 | 都提示"口令不正确，或文件已损坏 / 被篡改"，本机数据不变 | |
| V14 | 安全输入框 | 在主密码框里试中文输入法、粘贴、Tab、回车、Esc | 粘贴可用；回车提交；Esc 取消；不能复制出明文 | |

## AI 助手（P7 M5）

**需要的条件**：一个可用的 API Key（OpenAI 兼容服务或 Anthropic）；一台能 SSH 的测试主机。

| # | 项目 | 怎么测 | 预期 | 结果 |
|---|---|---|---|---|
| A1 | 未配置 | 没填 Key 时点工具栏"AI" | 抽屉说明尚未配置，有"去设置"；不发出任何请求 | |
| A2 | 配置与测试连接 | 设置 → AI 助手，选服务商、填 Base URL、模型、Key，点"测试连接" | 成功提示；Key 显示"已保存"，可替换 / 移除；主密码库锁定时先弹解锁框 | |
| A3 | 首次说明 | 第一次提问 | 先说明会把什么（脱敏后的最近 40 行 + 问题 + 之前的对话）发到哪个地址；取消则不发送 | |
| A4 | 多轮对话与流式 | 问"找出占用 3000 端口的进程"，再问"把刚才的命令改成只看 nginx" | 回答逐字出现；第二轮理解上一轮；命令以卡片显示，可"停止生成" | |
| A5 | 插入命令 | 点命令卡片的"插入" | 进入发送确认对话框，危险命令标红；不确认就不会执行 | |
| A6 | 脱敏 | 在终端里 `cat` 一个含 `PASSWORD=`、私钥块的测试文件后提问 | 提问气泡下显示"已去除 N 处敏感内容"；对话记录里看不到原文 | |
| A7 | 解释报错 | 让终端出现 `connection refused` 之类的报错（串口会话也试一次） | 右上角浮出"解释报错"，点击后抽屉打开并针对该行提问 | |
| A8 | 历史与继续 | 点"新对话"开始新对话；重开 App 后点"历史"打开旧对话继续问 | 旧对话完整保留，可接着问；可单条删除 | |
| A8a | 新对话状态与提示 | 空对话、历史列表、已有对话分别查看「+ 新对话」；切换「保存对话」并悬停 | 空对话禁用；历史列表可直接返回空对话；提示即时反映保存开关，保存失败时提示未能保存；新问题前不产生历史空行 | |
| A8b | 执行中开始新对话 | 执行命令、等待审批、等待「继续」时点「新对话」；先取消再确认；保存关闭时再试 | 均先显示「停止并开始新对话？」；取消保留当前执行；「停止并新建」停止并重置，开启保存时可从历史查看已完成内容；关闭保存时文案说明不会保存 | |
| A8c | 删除当前对话 | 从历史打开一段旧对话，再打开历史并删除它，然后开始新问题 | 历史列表保持打开；旧对话不再出现；新对话无旧的只读 / 续跑状态，创建时间为新建时间 | |
| A9 | 关闭保存 / 清除全部 | 设置里关掉"保存对话"再提问；然后"清除全部对话" | 关闭后重启不再有新记录；清除后历史为空 | |
| A10 | 错误提示 | 填错 Key；把模型名写错；断网 | 分别提示 Key 无效、模型不存在、网络错误（中文），可"重试" | |
| A11 | 思考等级 | 设置里依次选「默认」「关闭」「高」各问一次同一个问题；再选一个模型不支持的等级（如给不推理的模型选「高」） | 「默认」与之前行为一致；「高」等待更久，抽屉先显示"正在思考…"再出正文；不支持时提示"当前模型不支持所选思考等级" | |
| A12 | Anthropic 自定义地址 | 选 Anthropic，Base URL 填代理地址（带或不带 `/v1` 都试），保存后提问；再切回 OpenAI 兼容再切回来 | 请求发到代理地址；首次向新地址发送会重新弹出说明；切换服务商后各自的地址和思考等级保留 | |

## 菜单栏

使用临时主机库、测试主机和无敏感内容的剪贴板。调试版可设 `SHELLMATE_DEMO=proto:main`、`proto:local`、`menu-empty` 或 `about`，并为每个场景指定不同的 `SHELLMATE_MENU_DUMP` 文件。转储列为菜单、项目、快捷键、勾选、实际禁用、当前焦点动作可用性；服务与分隔线没有动作。

## AI 命令输出查看

使用调试原型和临时 `SHELLMATE_DATA_DIR` / `SHELLMATE_LOG_DIR`，不连接真实主机或模型。复制测试先保存剪贴板所有格式，结束后恢复。

| 项目 | 操作 | 预期 |
|---|---|---|
| 短输出 | `proto:ai-output-short`，复制输出 | 无“已保存 · UUID”；命令实际打印的 UUID 保留 |
| 全文与折叠 | `proto:ai-output-expanded`，收起后重新展开，⌘↓ 跳到底部 | 8 行首尾预览；展开可读到 `FINAL-EVIDENCE`，不调用模型 |
| 全文复制 | 在同一场景分别点“复制全部”和聚焦输出后 ⌘A、⌘C | 两份内容相等，包含 3,501 行以及中间的 `MIDDLE-EVIDENCE` |
| 历史 | `proto:ai-output-history`，展开和复制 | 阅读操作正常，不能因此执行命令 |

| 清理与截断 | `proto:ai-output-missing`、`proto:ai-output-retained` | 分别显示已清理和部分内容未保留，复制标签不冒充完整输出 |
