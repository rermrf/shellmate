# 多 AI 对话并行与多终端任务：实施计划

状态：M1–M7 已实现，2026-11-26。首版结果见第 13 节；后续终端资源模型及执行通道修订见第 14 节。第 1–13 节保留历史设计与验收记录，其中“加入/移除范围”、名称匹配授权和子代理固定独立通道的约定已被第 14 节替代。

## 1. 目标与交付边界

同时满足两个使用场景：

1. 本地终端 1 的 AI 对话仍在执行，用户切到 SSH 终端 1，立即创建新的 AI 对话；两段对话各自运行、接收消息与审批。
2. 同一 AI 对话发现应用已打开的终端，选择本机和 SSH 两个目标，读取两侧目录或执行有明确目标的操作，汇总比较结果。

采用用户确认的方案 3：**独立 AI 对话列表＋按当前终端快捷新建**。在此基础上增加**默认终端＋任务目标集合＋每次工具调用的目标**。终端标签焦点、当前可见 AI 对话和工具执行目标各自独立。

分两个交付批次：

- **第一批 M1–M6**：独立运行实例、多对话切换与并行、终端发现/读屏/命令路由、按目标审批、跨终端子代理和恢复。可完成本地＋SSH 的调查与基于命令结果的对比。
- **第二批 M7**：结构化只读目录比较工具，输出可分页的差异清单，避免由模型解析海量原始文件列表。

多会话基础完成不代表结构化目录比较完成。各批次独立验收；不包含自动同步、跨机文件覆盖/删除、自动创建 SSH 连接、跨应用终端控制或嵌套子代理。

继承现有消息队列、立即处理、停止回复与停止任务分离、完成通知重试、每轮计时、子代理对话页、统一工具卡片和网页工具。新增功能不能回退这些行为。

## 2. 实施前基线与调整方向

| 位置 | 当前实现 | 调整方向 |
|---|---|---|
| `workspace.rs` / `workspace/ai.rs` | 每个 Workspace 一个 `ai_drawer`；焦点终端触发 `sync_context` | 抽屉只选择/渲染对话，运行实例由应用级管理器持有 |
| `ai/panel.rs::sync_context` | 忙碌时保存 `next_context`，空闲后允许改绑定 | 只更新“当前选中终端”的导航提示，不改已有对话的执行目标 |
| `new_conversation` / `load` | 调用 stop、清理并替换当前实例 | 新建独立实例；打开活跃历史回到同一实例，不重复启动 worker |
| `ai/panel.rs` / `agent_ui.rs` | worker 接收、ACK、审批与每秒维护绑定窗口/Drawer | 运行态归协调器；视图订阅状态，后台对话也可提交日志、ACK、继续执行 |
| `workspace/hub.rs` | 应用级 `session_ids`，`Route::Session(id)` 可定位移动后的标签 | 复用路由，增加可供 AI 使用的稳定引用和连接代次 |
| `ai/exec.rs::AppExecutor` | 一个 `Binding` | 按调用从终端目录解析目标，创建该次执行的绑定快照 |
| `ai/host.rs::Host` | 一份 `mode` 和 `alive` | 取消属于对话；可用性和权限属于每个目标，单目标断线不取消整轮 |
| `ai/subagents.rs` | 子代理复制父实例唯一绑定与记忆范围 | 继承允许的目标集合，并明确自身默认终端与本轮范围 |
| `shellmate-store::ai` | 一个 `host_id`，运行态 JSON，日志/通知事务 | 保留旧字段兼容，增加多终端关联和版本化目标元数据 |
| `files/source.rs` / `shellmate-sftp` | 已有本机与 SFTP listing、文本读写能力 | 抽取只读接口供 M7 使用；不把文件面板实体传入 worker |

已有终端 ID 是应用内单调分配值，跨窗口移动不需要重新分配。不能将它原样当作跨应用重启的持久标识。

## 3. 用户交互

### 3.1 新建与切换对话

AI 抽屉顶部保留当前风格，增加紧凑对话选择器和新建入口：

```text
AI 助手     检查远程日志 ▾       ＋
默认终端：远程终端 1 · prod-web-01
本次目标：[本地终端 1] [prod-web-01] ＋
```

- 对话选择器按“需要处理、运行中、最近对话”展示。每行显示标题、目标摘要、状态、运行时长/未读标记，不显示内部 UUID。
- `＋` 的主操作是“在当前选中终端新建”；菜单还可提供“使用当前对话的目标新建”。没有选中终端时可建无终端对话，网页查询仍可使用。
- 新建始终可与其他已运行对话并行。已有空白草稿可直接复用，避免连续点击制造大量空白记录。
- 切换终端时，已显示的 AI 对话保持不变。若两者不同，显示“当前对话使用本地终端 1”，并提供“为远程终端 1 新建”和“定位默认终端”。
- 切换 AI 对话不自动切换终端标签、不重启 worker；点击“定位终端”才激活对应标签和窗口。
- 每段对话保留消息、队列、子代理页、工具展开、阅读位置和输入草稿。已提交消息目标固定，不随之后的界面切换变化。
- 活跃对话与历史使用同一入口。打开仍在运行的历史必须命中同一 `ConversationRuntime`，而非从 SQLite 复制另一套状态。

### 3.2 选择多个终端

- 新对话默认以创建时的焦点终端作为默认目标；第一次发送前允许调整。已有任务不因标签焦点变化改目标。
- 使用目标选择器勾选应用内已打开的终端；列表提供本机/SSH、窗口名、终端名、连接状态、主机标识和忙碌状态。
- 输入支持 `@终端`，选择后形成真实 `SessionRef` 附件，展示友好名称。普通文字的“终端 1”不作为工具路由键。
- 明确自然语言“比较本地终端 1 和 prod-web-01”可自动解析；无歧义且用户已经指定的目标直接加入本轮，不额外要求重复确认。重复名称、多个同主机标签或缺失路径才询问消歧。
- 对话中可保留常用目标；每轮记录实际使用的集合及目录。缩小本轮范围不清除已获得结果；移除目标后阻止新的调用，正在执行的操作保留并可明确停止。
- 默认终端只有一个；多目标调用必须明确 `session_id`。没有默认目标的旧调用返回“请指定终端”，不能隐式落到当前焦点标签。
- 列出终端是发现能力，不自动发送全部终端屏幕内容，也不等于用户要求操作所有终端。用户已指定范围内的正常操作直接遵循原审批规则；对未包含且任务未明确要求的目标，展示一次目标选择请求，不逐条重复询问。

### 3.3 后台运行、审批与通知

| 行为 | 预期 |
|---|---|
| 切换 AI 对话、隐藏抽屉 | 已有执行继续；不调用 stop/retire/discard |
| 后台对话完成 | 更新选择器未读状态和轻量通知，不抢当前对话或终端焦点 |
| 后台对话需要审批 | 选择器与 AI 入口显示待处理数；通知注明对话、目标终端和动作；点击进入对应卡片 |
| 在列表停止回复 | 仅停止对应对话继续生成/调度；沿用后台任务继续运行的既有语义 |
| 停止某任务 | 按 conversation/run/task 身份取消；不影响同名任务或另一对话 |
| 从列表移除已完成对话 | 仅关闭该视图项，已保存历史仍存在 |
| 关闭仍活跃的对话 | 默认保留后台运行；“停止并关闭”是明确的另一操作，不把关闭抽屉等同取消 |
| 关闭终端 | 提示会影响哪些对话/任务；关闭后只中断该终端相关操作，保留其他目标结果 |
| 断线重连 | 旧执行租约失效；不重放未知完成状态的调用；重连后允许显式继续 |
| 退出应用 | 停止所有活跃实例，保存已知状态；重启后标记中断/待恢复，不自动执行 |

关闭保存时，对话在应用内切换/隐藏仍保留内存状态；显式关闭该对话或退出时清理。UI 必须将“关闭抽屉”“停止任务”“删除历史”区分开。

### 3.4 统一工具卡片

复用 `tool_model.rs` / `tool_ui.rs`，新增目标摘要行，例如：

```text
▸ 执行命令                         已完成 · 0.8 秒
  获取目录文件清单
  prod-web-01 · SSH · /srv/app · 后台执行
```

主/子代理共用，审批也展示同样的目标。点击工具标题仍然只展开，定位终端和查看子对话是独立操作。不可通过点击卡片标题顺便改变执行目标。

顶部选择器、目标标签遵循现有 Flyme 风格和亮暗 palette。窄抽屉目标以“2 个终端”折叠摘要展示，不堆多排标签挤掉正文。审批在其他对话中时不覆盖正在输入的编辑器。新增快捷键必须保留中文输入法、斜杠菜单、Esc 返回子对话与对话列表的优先级。

## 4. 运行架构

```text
应用级 ConversationManager
 ├─ ConversationRuntime A ─ 本地终端 1
 ├─ ConversationRuntime B ─ SSH 终端 1
 └─ ConversationRuntime C ─ 默认本地终端 1，范围包含本机＋SSH
              │
       按调用解析 TargetRouter
              │
       应用级 SessionCatalog
              │
       本机后台 / SSH exec / 交互 PTY / 只读文件接口

各窗口 AI 抽屉 ─ 订阅指定 Runtime，保留本地视图状态
```

建议新增模块名可在实施时按代码风格微调，职责不混用：

- `ai/conversation_manager.rs`：对话实例注册、创建、选择、历史查找、关闭、应用退出、全局通知索引。
- `ai/conversation_runtime.rs`：每对话唯一的主 worker、Control、日志、待 ACK、run scope、Tasks、审批回复通道、计时、持久化与完成续答；不依赖某个 Window 的存活。
- `ai/conversation_ui.rs`：对话选择器、状态摘要和当前终端快捷新建；不拥有运行器取消责任。
- `ai/session_catalog.rs`：应用内会话目录、生命周期事件、路由引用；GPUI 所有权留在应用线程，通过类型化桥接请求读取屏幕/启动交互命令。
- `ai/target_router.rs`：解析调用目标、校验范围、连接租约、目录及权限，形成执行快照。
- `shellmate-ai/src/session_tools.rs`：工具 schema、参数校验、结果契约；不依赖 GPUI。
- M7 的 `ai/directory_compare.rs`：可取消的结构化清单/内容比较，复用只读文件接口。

先提取现有执行/持久化逻辑再接多实例，禁止只保存多个 `ConversationState`、切换时继续复用同一个 `abort` / `Host` / `tasks`。也不能依靠把多个 Drawer 隐藏在树里来维持执行：当前 `cx.spawn_in(window)`、审批持有和 Drop 清理均需要审查。

每个 Runtime 最多一个具有工具能力的主循环，不因切页或收到多个完成通知重复启动。多个 Runtime 可以并行；每个子代理仍属于唯一父对话。输出、审批和事件身份至少包含 conversation/run/agent/call，不能只使用 `agent-1` 或某个 provider call ID。

各窗口可以订阅同一运行实例；日志与队列串行进入协调器。视图草稿/滚动位置按窗口保留，不互相覆盖；已提交消息按稳定 ID 去重。跨窗口打开同一对话不额外启动模型。

## 5. 终端身份、范围和快照

### 5.1 引用

建议模型收到的 `session_id` 是不透明引用，由应用生成，不是主机名、列表位置或 shell PID。内部映射：

```text
SessionRef → { app_epoch, existing_session_id, connection_generation }
             → 当前窗口 Route::Session(existing_session_id)
```

- 复用现有全局 `Services.session_ids`；应用重启生成新的 app_epoch，旧模型引用失效。
- 标签改名/跨窗口移动保持会话身份；路由在执行时通过 Hub 找当前 owner，不继续持有旧窗口路径。
- 终端关闭/重启、SSH 换连接后 generation 变化；调用调度、审批通过及实际执行前检查同一个租约。
- 目录变化不是连接变化；每轮每个目标建立一次 cwd 快照。多目标新加入时建立该目标快照；普通前后台切换和自动续答不改变它。
- 会话恢复信息可以包含主机 ID、协议、显示名、原目录和已知身份提示，用于让用户重新关联；不能把持久化数字 ID 当作仍存活的执行目标。

### 5.2 运行与上下文

`RunScope` 包含默认目标、参与目标快照、目标范围版本，以及每个目标的权限/能力信息。`ResolvedTarget` 至少包含：会话引用、连接代次、本机/远端属性、执行通道、主机身份、cwd、存活租约、目标权限与记忆范围。

调度前按目标解析，审批通过后再次检查租约；执行开始后不能因为选中标签改变而重新解析成另一个目标。旧目标失效返回结构化 `target_disconnected` / `target_changed`，不回退到本机或当前标签。

后台本机/SSH 命令的相对路径基于该目标的轮次快照。SSH exec 是独立 shell，不继承交互 shell 的 `cd`、venv 或 `su` 状态：需要相对目录时以正确引用的工作目录显式执行；目录未知必须明确报错或使用用户给出的绝对路径。交互终端命令尊重该终端实际 shell 状态，不为了复用后台路径逻辑悄悄注入 `cd`。

`read_terminal` 返回采样时间、目标身份、目录是否已知、最近输出和是否截断；沿用现有终端上下文内容规则，不新增自动脱敏。一次可读多少行和字节有上限，长历史不自动发送。主机记忆按使用目标读取/标注，全局记忆可共享；自动记忆写入必须明确对应主机或全局，不能把默认主机的环境覆盖到另一目标。

### 5.3 授权与权限

- 创建时的默认目标、用户点选的目标和发送消息中无歧义指定的终端都是本轮范围依据；明确的用户要求优先，不新增重复确认步骤。
- 模型提出的目标补充如果已有用户授权依据，由协调器应用；不存在依据时只产生一次待选择请求。模型不得通过改写一个 `session_id` 字符串扩大范围，工具输出中的指令也不构成用户授权。
- 主机权限模式在目标解析时读取，审批通过时复核相关变更。多个目标权限不同，UI 显示“按目标设置”并可展开查看，不能给整段对话伪装一个 Full 模式。
- 目标可见、可读屏、可执行能力分别报告。某协议不支持后台或文件接口时明确返回能力不可用，不模拟成功。
- 进入审批后变更执行目标须使原审批失效并按新目标重新判定；已授权范围内普通只读工具遵循既有策略，不增加每次选终端的确认。

## 6. 工具契约

| 工具 | 首期参数 | 返回/行为 |
|---|---|---|
| `list_sessions` | 可选名称/协议/状态筛选 | 应用所有窗口内已打开终端的分页元数据；包含可用能力和范围状态，不附全屏日志、凭据或自动连接已保存主机 |
| `read_terminal` | 必填 `session_id`，可选 `lines` | 指定终端的输出快照、目标身份、采样时间、截断标记 |
| `run_command` | 增加可选 `session_id`、后台绝对目录 `cwd`，保留 `target` 和原参数 | 明确“哪个环境”与“交互/后台”两个维度；省略目标时只使用本轮默认目标，无默认时失败 |
| `agent` | 可选 `session_ids`、`default_session_id` | 不扩大父任务已批准范围；未指定时继承父范围，单目标委派可以收窄到一个；主/子代理使用同一终端发现/操作接口 |
| `send_agent_message` | 沿用原接口 | 消息只影响该子代理，不隐式更换它的默认终端；目标范围变化走统一路径 |
| `read_output` / `stop_task` / `wait_tasks` | 沿用会话内任务引用 | 不重新选择终端；从任务注册信息取得原目标及连接代次 |
| `memory` | 多目标时增加明确的主机/全局作用域 | 使用该目标记忆配置；默认目标明确时兼容旧调用 |
| `compare_directories`（M7） | `left/right={session_id,path}`、比较模式、排除规则、分页/续跑引用 | 结构化差异、统计、来源时间、未完成项及结果引用 |

结果类型统一包含成功/失败、来源引用和可理解错误。工具 schema、解析器、提示词、可用工具清单和两条 provider wire 同步更新。显示中不露内部引用；历史 raw 参数可检查，执行日志记录实际解析的目标快照而非只记模型请求的名字。

主循环仍有序执行工具；并行能力通过独立对话、已有后台任务、子代理及 M7 内部受控并行实现，不为新工具一次性引入任意工具调用并发执行。

## 7. 多实例资源与生命周期

- 交互终端以 SessionRef/lease 为粒度互斥，跨对话共享占用状态。新命令遇到 busy 返回所属对话的友好提示，不自动抢占或偷偷改为后台。第一批不增加隐式交互命令队列，避免过时命令在稍后突然执行。
- 独立本机进程、SSH exec 通道、网页请求可以并行。每个对话自己的步数/计时/取消保持隔离；服务商限流、搜索并发与同 SSH 连接的通道压力由应用级资源协调器管理，不能按新开对话数量成倍绕过限制。
- 已有每父对话子代理并发设置保持语义；本次不新增“主代理可以而子代理不可”的工具限制。需要等待资源时显示等待状态，用户仍可补充消息/取消。
- 任一目标断线只终止该目标的在途操作和审批。多目标任务保留其他结果，由模型收到明确失败后重新决策；没有可用终端时仍可解释已收集结果。
- 标签跨窗口移动与窗口关闭分别处理：移动只是 owner 更新；真正关闭终端则吊销租约。隐藏抽屉或关闭查看该对话的窗口不销毁运行器。应用退出遍历管理器中所有实例，不能只停止当前窗口可见抽屉。
- 保存失败、队列 ACK、完成通知去重和迟到事件防复活沿用现有事务边界，由 Runtime 执行。完成通知不依赖任何页面的一秒定时器；重新打开只订阅已有结果。
- “清除全部 AI 对话”需要覆盖管理器所有运行实例后再清理存储/输出。删除单个对话只吊销其运行代次；其他对话的子任务/输出/审批不受影响。

## 8. 持久化与兼容

建议在当前 v11 基础上增加 v12 迁移（实施时若已有其他迁移占用版本则顺延），新增 `ai_conversation_targets`：

```text
conversation_id → ai_conversations(id), ON DELETE CASCADE
target_key      对话内目标身份，不等于可直接使用的运行期引用
host_id         可空；本机及临时主机依既有规则表达
role            default / participant
snapshot_json   名称、协议、原目录、关联提示、schema_version
PRIMARY KEY(conversation_id, target_key)
```

- 旧 `ai_conversations.host_id/session_label` 保留作为默认目标和旧历史兼容信息，不再作为“整段对话只属于这一台主机”的唯一依据。
- 运行态 JSON 增加版本化默认目标、轮次参与目标快照及必要状态；语义 Step 增加可选实际目标 metadata。普通文本和旧调用可以继续读取，不批量改写旧用户日志。
- 迁移、保存、队列确认、目标关联和运行态使用一致事务。保存关闭时不新增这些持久内容，维持现有输出关闭清理策略。
- 重启后元数据仅用于展示/重新关联。未完成状态转为中断或待恢复；不复活 OS 进程、SSH exec、旧审批 sender 或继续发送未确认命令。
- 明确选择仍可用的原目标后允许继续；同名新终端、不同连接代次、旧引用不存在不能靠名称自动接管。
- 活跃运行器与 DB 历史打开去重；多个窗口均打开同一历史时只产生一个 Runtime。

## 9. 结构化目录比较（M7）

### 9.1 比较语义

- 左右两侧各有显式目标和绝对根路径；相对路径必须基于对应目标 cwd 解析并记录，不能两侧共用默认终端目录。
- 支持两种模式：`metadata` 比较名称/类型/大小/时间；`content` 用文件内容摘要确认相同。只有内容比较完整且成功时才能声明内容一致，大小时间相同不代表内容相同。
- 默认精确区分大小写和原始路径；另行提示大小写/Unicode 归一化冲突，不静默合并。保持本机与 POSIX 远端路径差异，不把远程路径当本机路径。
- 默认比较软链接本身，不跟随链接、不越过根目录；特殊设备、套接字等记录为跳过。排除规则明确展示，隐藏文件不在没有说明时默认忽略。
- 不执行同步或修改；发现差异只返回只读证据，后续写入/同步是独立任务。

### 9.2 执行策略

复用/抽取 `FileSource` 的本机与 SFTP 只读能力，提供流式 listing/stat/read，不要求打开文件面板。优先避免依赖远端 GNU 工具或安装 Python。

按相对路径合并清单；大小不同可直接判不同，同大小且需内容确认时流式计算摘要。文件内容在本地进程比较时可能需要经 SFTP 传输，UI 展示进度和读取字节数，不能称为零流量。已有远端摘要工具的优化可后续加入，需经过相同目标路由和执行规则。

结果包含：仅左侧、仅右侧、类型不同、内容不同、仅元数据不同、已确认相同、跳过、读取失败、比较中发生变化。读取前后检查可用 revision/stat，文件变动时标为不确定；整个目录比较是一定时间区间内的观察，不冒充原子文件系统快照。

清单/比较结果本地落盘并分页；模型接收统计与差异摘要，用户可展开全部差异。首版每批处理建议默认 10,000 项/1 GiB 内容读取，命中上限返回可继续的检查点与“部分完成”，不能标为全部一致；数值集中配置并在用户要求扩大范围时可调整。目录遍历、摘要和结果写入必须可取消。

### 9.3 结果界面

复用统一工具卡片，在摘要中显示两侧终端/路径与差异统计；展开显示差异列表和筛选。选择文本文件可看带两侧来源的 diff；二进制只展示摘要/大小差异。窄抽屉用纵向左/右来源与分组行，宽视图才显示并排列。完整结果可在本地查看，不因模型输出预算截断用户可读数据。

### 首版约定与边界

- `list_sessions` 使用可选 `query` 匹配名称或协议，每页 50 个；没有单独的状态过滤字段。`read_terminal` 默认 40 行，允许 1–500 行，约 64 KiB 上限；只取已授权目标，不自动脱敏。
- `@` 点选会加入对话目标集合，并将稳定引用作为消息上下文附件保存。移除输入附件不会撤销已有目标范围；需在终端选择器移除。自然语言仅匹配唯一终端名称，歧义或模型自行提出的范围外目标通过选择器处理，加入后再继续。
- 同一轮的目标 cwd 使用快照；后台调用可以显式提供绝对 `cwd`。SSH exec 不继承交互 shell 的虚拟环境、`su` 等状态，目录未知时不回退到本机目录。交互调用不能用 `cwd` 隐式更改 shell 目录。
- 共享并发上限为主/子代理模型请求合计 4、本机后台命令 12、每条 SSH transport 4、网页服务 3。模型上限在应用内共享，不是可调的服务商独立额度。等待资源仍可追加消息/停止。
- 目录比较默认核实内容，`metadata_only` 只比较元数据；排除项是相对路径前缀，不是 glob。每侧每批 10,000 项/1 GiB、总清单每侧 100,000 项、检查点 64 MiB，首版为固定常量。超过单文件读取上限会标为未核实；巨大单目录或总清单达到硬上限需缩小范围/排除项目，不能无限续跑。
- 模型每页接收 100 行，完整清单沿用本地输出阅读器，不受模型分页限制。扫描期间显示工具运行状态，返回时展示已核实字节数，没有逐文件实时进度。文本预览限两侧各 256 KiB 以内的普通 UTF-8 文件；重新读取并核对摘要，文件变化后要求重比，二进制显示摘要。
- 目录比较不是原子快照。使用可用 stat/revision 做读取前后检查，本机额外检查 inode 并拒绝最后一级软链接；SFTP 的时间精度和路径竞态无法完全消除。链接自身参与比较，不主动遍历链接目标；特殊文件或未核实项不会被当作内容一致。
- 应用重启后旧引用必须显式重新关联；读取历史不自动执行。关闭抽屉保留运行，关闭活跃对话使用“停止并关闭”，退出应用停止所有运行器。多窗口查看同一对话共享执行状态，输入草稿各自保留。

## 14. 终端资源与执行通道修订（2026-11-26）

实际案例中，列表返回 `mqtt_device_simulator — zsh`、`shellmate — zsh`、`shellmate-agent — zsh`，用户指定前两个简称执行 `ls`。模型选中了正确引用，但原路由因“未加入本轮范围”拒绝；选择器被自动打开，用户加入后也没有唤醒已结束的任务。这是资源模型的问题，不能仅靠增加名称匹配规则解决。

现行规则：

- 所有打开的终端都是 Agent 可发现、可按任务使用的资源。主/子代理调用均按稳定 `session_id` 解析，不再维护操作白名单或通过自然语言子串授予范围。
- 模型结合上下文理解简称、路径和序号。`list_sessions` 返回从 1 开始的 `number`、稳定引用及采样时间；“刚才第几个”沿用那次列表的引用，不能重列后按新位置替换。“每个终端”使用该任务发现的资源快照。
- 默认终端用于省略目标的兼容调用，切换标签或使用另一资源均不改变它。`Scope.targets` 只记录已引用终端及本轮 cwd 快照，保留原序列化格式。未知或过期引用仍失败，不自动重绑或回退。
- 创建子任务时终端引用是上下文提示；不限制其发现其他资源。继承上下文中的断线终端不阻止新子任务启动，明确指定失效目标仍返回错误。用户明确的只读、只操作某些终端等任务约束仍传递给子代理。

每条命令独立选择三个参数：

| 参数 | 含义 | 例子 |
|---|---|---|
| `session_id` | 哪个已连接终端资源 | 上次列表中第 2 个终端的稳定引用 |
| `target=terminal` | 在该页面现有 shell 执行并留下可见输出 | “每个终端执行 ls，我切过去看” |
| `target=background` | 对该资源使用独立本机进程或 SSH exec，结果进对话 | 文件调查、目录比较所需的辅助命令 |
| `run_in_background` | 是否立即异步返回，让 Agent 做其他工作 | 两种通道均可为 true；不迁移或重新启动进程 |

新 schema 要求模型显式提供 `target`，解析器兼容旧调用省略该参数。去掉整轮关键词屏蔽通道，以及子代理执行前/审批后的强制改写。同一轮可混合两种通道。专用读取/目录比较工具优先用于调查；页面 shell 的目录、虚拟环境、变量、su 状态不会由独立通道继承。

连接代次校验、每目标命令审批、审批后复验、终端占用检测、取消和输出捕获继续适用。终端占用不抢输入、不自动切换通道；独立通道目录未知不回退到应用或本机默认目录。页面命令不自动改变用户当前标签焦点。

UI 使用“可用终端”，提供定位、设为默认、引用；引用只附加稳定目标，不更改默认或授权。移除加入/移除范围按钮和自动弹出选择器行为。统一工具卡片分别展示“终端内/独立通道”和“异步任务”；结束等待仍允许后续交互。多个窗口用友好窗口编号，不展示内部 WindowId。

验证使用三份受控真实 PTY、临时目录和脚本化 provider 响应：发现列表后向前两个页面执行 `ls`，独立读取两侧文件，子代理在第二个页面异步执行；第三个默认终端不被写入、默认引用不改变。另有 OpenAI-compatible/Anthropic 双协议测试覆盖两种通道 × 两种等待方式，以及子代理参数与执行记录。这些测试验证实际执行与记录路径，不证明真实模型一定正确理解简称/序号；真实模型和真实 SSH 联调仍需人工验收。

修订验证结果：app 822 项通过、2 项外部环境测试忽略；AI 单元 36、agent 82、provider 22 通过，2 项外部 e2e 忽略。后续 UI 文案调整的输出阅读器 4 项回归通过。workspace/all-target Clippy `-D warnings`、构建和 `git diff --check` 通过。可用终端普通/窄窗、子代理审批窄窗、目录比较场景共 8 张亮暗截图；原生回放确认引用、设置默认、子代理审批切换通道、Esc 收起。日志和截图保存在 `/private/tmp/shellmate-resource-routing/`，全部使用临时数据，未对用户终端执行测试命令。


## 15. 持续服务与等待展示（2026-11-26）

用户案例“帮我运行这个项目”调用 `npm run dev` 时，模型选择 `target=terminal`，没有异步参数；10 秒后只结束 Agent 等待，Vite 仍占用原终端，也没有完成启动核验。此行为不能通过把界面上的“后台”改名解决，需要区分通道、等待和进程生命周期。

### 执行约定

`run_command` 增加可选 `service` 对象，适用于开发服务器、watch 等用户要求持续运行的进程。它自动启用异步，并由所属会话管理；与 `session_id` 和 `target` 独立，不迁移、不重启进程。

```json
{
  "command": "npm run dev",
  "target": "background",
  "session_id": "从 list_sessions 获得的终端引用",
  "service": { "ready_pattern": "Local:", "startup_timeout_secs": 10 }
}
```

- `ready_pattern` 是可选的原文片段，不是正则；最长 512 字节。依据实际启动配置选择，不能从未检查的项目猜端口/启动方式。
- 启动检查默认 10 秒，可为 1–60 秒；匹配输出返回“已出现就绪信号”，超时或省略片段返回“就绪待确认”，进程继续。输入“立即处理”、结束等待或停止回复可提前结束检查，不会顺带停止持续服务。
- 输出匹配只证明该日志出现，不等同 HTTP 健康。模型应按需在同一终端资源/主机检查 HTTP 或端口，给出实际地址和证据后完成本轮；`wait_tasks` 对仍运行的持续服务返回说明，避免无限等服务退出。
- 检查期间进程已退出，即便退出码为 0，也不能认定服务可用。错误与日志保留，已观测到的退出不能被就绪状态覆盖。
- 提示词默认将“启动项目/服务”安排到独立通道，先检查配置再启动。用户明确要求页面日志，或必须依赖页面 shell 状态时，模型可选 `terminal`；不做 npm/python 等命令名硬编码，不自动改写模型已选通道。旧调用不传 `service` 时沿用原行为。
- 不使用 `nohup`、`disown` 或 shell `&` 逃离管理。常驻进程保留输出、停止与断线处理；本机使用独立进程组，SSH 沿用 exec 通道。

### 生命周期和界面

子代理退出只取消其临时命令，已声明的持续服务由父会话持有。父会话以命名空间区分不同子代理的同名任务，能读取完整输出、停止服务并接收退出通知；子对话也保留原调用与输出。关闭抽屉/切换对话不终止服务，停止全部、停止并关闭、删除对话或退出应用会清理。应用重启不会恢复进程或自动重放启动命令。

输入框上方仅显示运行中的异步 shell 命令，附执行通道、目标和服务状态，以及“查看输出 / 停止”；窄窗分行，多条命令可滚动。移除重复子代理行与内部任务编号。子代理保留在对话中，仍可展开提示词、工具记录或进入子对话。

`wait_tasks` 仍是工具，继续保存输入和结果，UI 沿用统一展开交互，以无卡片背景的简洁状态行显示等待数量/已结束数量；完成后显示“已结束等待”，错误可展开。等待期间不再同时显示“正在思考”。服务无需退出就能结束本轮计时，后续用户输入不被常驻进程阻塞。
