# 已有终端的通用交互

首期覆盖应用内已经连接的本机 PTY 和 SSH shell 终端，主代理与子代理使用同一工具及权限路径。Vim、less、监控和菜单是验证场景，不新增应用专用工具。不包含 Agent 鼠标输入、终端图片、独立后台 PTY。

## 工具

- `read_terminal(screen=true, session_id, region?)`：读取程序当前屏幕，不受用户滚动历史影响；保留物理行、光标行列、反色/颜色/粗体/下划线、备用屏幕及按键模式。`screen=false` 兼容原历史读取。region 使用 0 起算单元格坐标。
- `terminal_input(session_id, screen_id, purpose, actions)`：text 键入字符，paste 使用程序启用的括号粘贴，key 使用终端模式编码按键。每批 1–8 个动作、最多 40 次按键；单段文字最多 4096 字节。text 不含换行/控制字符；回车独立发送。无括号粘贴时拒绝多行 paste。输入返回 actions_sent 和当前画面，不能据此声称业务操作完成。
- `terminal_input(release=true)`：交还一个终端，不发送 Ctrl-C、不退出程序。
- `wait_terminal(session_id, text?, fingerprint?, stable_ms?, region?, timeout_ms?)`：等文字出现、观察区域改变或稳定；多个条件同时满足才 matched=true。最长 10 秒，超时返回当前屏幕，不占模型请求名额。持续刷新界面应观察稳定菜单/状态区域而不是永远等待整个屏幕停止刷新。

## 控制与校验

一次交互绑定一个任务控制器与稳定终端引用。读屏只读；首次写入取得控制，一个终端同时只允许一个 Agent 写入，多个终端可由同一 Agent 操作。连接替换、尺寸改变、观察区域内容/样式变化、手动输入或已发送输入都会使旧画面引用失效；引用有效期 120 秒。

输入前与审批后重新检查目标、权限和画面。用户手动键入/粘贴/点击终端暂停该终端的自动输入；切换标签或窗口焦点本身不会接管。暂停后读屏不能偷偷恢复控制，只有用户点击「允许继续」后才可重新读屏输入。停止/结束 Agent 或回收任务会释放其控制，不杀死 TUI。跨窗口路由不抢焦点。

默认/自动审批下，第一次交互需批准，随后同一控制范围的方向键、Tab、Home/End、PageUp/PageDown 可继续；文字、Enter、Escape、控制组合等保守视为可能改动状态，需单独批准。Full 遵循已有完全访问选择；直接可识别的红线命令文字仍需批准。按键在任意程序中的业务含义不能由通用终端层可靠推断，不能将“成功写入”描述为“只读操作已验证”。审批界面展示目标、目的和输入，不允许将其改成 shell 命令或切换到独立通道。

## 记录和界面

复用统一工具卡片，读屏结果显示等宽行、光标/尺寸/终端信息，原始样式数据随日志保留。终端上方提供操作状态与接管/恢复入口。旧历史回放不自动重发按键，也不恢复旧控制权。需要用户决策时使用 ask_user。

## 验证

覆盖三种模型协议、主/子代理身份、拒绝审批、审批中断线、控制竞争、手动接管、过期/变化画面、区域忽略动态指标、尺寸变化、App Cursor、括号粘贴、宽字符与高亮、超时和停止。windowless GPUI 模型测试通过真实 PTY 驱动 Vim 编辑临时文件、less 搜索和退出；不使用用户终端或文件。原生 UI 样本 `proto:ai-terminal-interaction` 为惰性菜单后端，无网络和 shell，用于检查接管入口及屏幕结果显示。真实远端 SSH 和模型 API 的组合行为仍需实际环境验证。
