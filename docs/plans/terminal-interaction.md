# 通用终端交互与独立 PTY

覆盖应用内已有的本机 PTY 和 SSH shell，以及 Agent 新建的独立 PTY。主代理与子代理使用同一工具及权限路径。Vim、less、监控和菜单是验证场景，不新增应用专用工具。不包含终端截图、像素鼠标协议和应用重启后的进程恢复。

## 工具

- `read_terminal(screen=true, session_id, region?)`：读取程序当前屏幕，不受用户滚动历史影响；保留物理行、光标行列、反色/颜色/粗体/下划线、备用屏幕及按键模式。`screen=false` 兼容原历史读取。region 使用 0 起算单元格坐标，只裁剪返回内容，后端仍保存完整物理画面作为输入基准。
- `terminal_input(session_id, screen_id, purpose, actions, guards?, observe?)`：text 键入字符，paste 使用程序启用的括号粘贴，key 使用终端模式编码按键，也接受单个可打印字符（如 6、?、k，区分大小写）。每批 1–8 个动作、最多 40 次按键；单段文字最多 4096 字节。text 不含换行/控制字符；回车独立发送。无括号粘贴时拒绝多行 paste。输入返回 actions_sent、changed、condition_matched、observation_status 和当前画面，分别表达已发送、画面变化、指定条件满足，不能据此声称业务操作完成。
- `terminal_input(release=true)`：交还一个终端，不发送 Ctrl-C、不退出程序。
- `wait_terminal(session_id, screen_id?, text?, absent_text?, exited?, stable_ms?, region?, timeout_ms?)`：等文字出现/消失、相对 screen_id 的区域变化、稳定或退出；多个条件同时满足才 matched=true。screen_id 绑定后端保存的完整基准；可从该基准提取不同 region，对同一范围进行比较。等待期间持有基准，不受后来读屏挤出缓存影响。旧 fingerprint 参数仍可解析，但必须对应缓存中的同区域基准；不在新 schema 中提供。最长 10 秒，超时返回当前屏幕，不占模型请求名额。持续刷新界面应观察稳定菜单/状态区域而不是永远等待整个屏幕停止刷新。

- `create_terminal(session_id, command, cwd?, purpose, columns?, rows?)`：指定来源终端的本机或 SSH 连接，新建独立交互程序。默认 100×30，不抢焦点，不占用原终端。返回新 session_id，继续复用读取、输入和等待工具。目录使用显式绝对路径或来源的已知目录；新 shell 不继承来源 shell 的临时变量、激活环境和别名。
- `manage_terminal(session_id, action, purpose, columns?, rows?)`：只管理本会话创建的终端。stop 停止程序并保留画面；close 停止并移除资源；resize 修改尺寸，范围 20–240 列、5–100 行。来源用户终端不能通过此工具关闭。
- `terminal_input` 新增 click（左/中/右键）、scroll（正数向下，负数向上，1–20 行）与 drag（左键，最长 80 单元格）。坐标从 0 起算，点击和拖动全路径必须落在已观察区域内。根据应用的鼠标模式使用 SGR、UTF-8 或传统协议，不支持时返回明确错误。每个动作包含完整的按下/移动/释放，不跨调用保持按住状态，不驱动系统指针。

## 独立终端生命周期

本机独立程序使用单独的 PTY 与进程组，SSH 使用指定连接的新 PTY exec 通道。原有后台命令继续使用非 PTY 通道，不能把已启动的普通进程无损转换为 PTY。源码中的 Catalog 保留独立资源，刷新窗口和关闭来源标签不移除独立终端；SSH 传输真正断开仍会使其程序通道失效。

主会话持有资源，子代理完成后释放输入控制但保留程序。停止回复不停止程序；停止全部任务停止程序；关闭/删除会话及退出应用回收资源。已停止/退出的终端仍可读屏，返回 ended=true；只有显式关闭才移除引用。创建取消和失败会清理尚未交付的本机进程或 SSH 通道。每会话最多 8 个、全应用最多 32 个独立终端，已退出但未关闭的终端也占额度。

运行任务及创建工具卡片提供「查看终端」。查看窗口与后台实体分离，收起或关闭查看窗口不会退出程序，重新打开保持原画面；窗口显示完整终端视图与接管入口。查看保持 PTY 行列尺寸，超出窗口可滚动；尺寸通过 manage_terminal 修改。停止程序保留最后画面，不提供自动重新连接/重启提示。历史回放不会重建进程，已关闭资源显示关闭状态。

独立终端遵循现有本机/主机权限：默认和自动模式需批准创建、管理和有状态输入；Full 允许，直接可识别的红线命令仍批准。审批后验证权限、来源连接和任务状态。普通导航键的获批规则与已有终端相同，鼠标不能被当成只读导航免批。任意 TUI 的按键/鼠标业务效果仍由 Agent 判断并遵守用户任务。

## 控制与校验

一次交互绑定一个任务控制器与稳定终端引用。读屏只读；首次写入取得控制，一个终端同时只允许一个 Agent 写入，多个终端可由同一 Agent 操作。连接替换、尺寸/终端模式改变、手动输入或已发送输入会阻止使用旧画面发送动作；引用有效期 120 秒，最多缓存 32 帧。完整基准最多 160000 单元格，每次读屏输出最多 40000 单元格。

没有 guards 时，输入前比较完整画面的内容、样式及光标，region 不能缩小默认检查范围。动态 TUI 可明确给出最多 4 个 Guard：region 内不含谓词时要求区域保持不变；提供 text、absent_text 或 cursor 时，谓词必须在基准与当前画面均成立。条件必须位于已经返回给模型的区域内。终端模式、连接身份、尺寸和控制权不被谓词放宽。通用终端没有语义控件树，应用能检查这些条件是否成立，但不能证明模型选择的条件充分；工具规则要求使用操作相关的菜单、选中项或输入框，不能只用标题/空白规避校验。

拒绝输入返回结构化 code、message、actions_sent、changed_rows，尽可能附带新的完整 screen，模型可直接根据反馈修正操作。手动接管、画面变化、引用失效、参数无效、连接变化、占用和写入错误分别表示。拒绝或部分写入后不自动重发。

输入前注册输出通知、取得观察区域的最新画面，写入后在异步层短暂观察。observe 默认最多 600 毫秒，允许 0–2000 毫秒；未指定目标时等画面变化并短暂安静 60 毫秒，持续动画到时返回最新画面。text/absent_text/stable_ms 是明确的观察条件。短观察和长等待由终端输出事件唤醒，另设稳定/超时计时器；不在 UI 线程等待、不持有模型请求名额。输出无变化时返回 no_change，已发送的动作不会重发。等待或观察可被用户新指令、停止、接管和断线打断；已发送输入不回滚。尺寸/模式变化需重新观察。程序退出不误报超时。

文字后是否同批回车能被识别取决于 TUI 的输入解析；工具仍允许短动作批次。通用规则要求文本输入后先观察字段内容，再发送 enter 提交，不添加固定长延时，也不自动补回车。动作无进展时先检查画面和布局、程序内帮助，再决定外部查询；最终回复前核对当前实际状态。

输入前与审批后重新检查目标、权限和画面。用户手动键入/粘贴/点击终端暂停该终端的自动输入；切换标签或窗口焦点本身不会接管。暂停后读屏不能偷偷恢复控制，只有用户点击「允许继续」后才可重新读屏输入。停止/结束 Agent 或回收任务会释放其控制，不杀死 TUI。跨窗口路由不抢焦点。

默认/自动审批下，第一次交互需批准，随后同一控制范围的方向键、Tab、Home/End、PageUp/PageDown 可继续；文字、Enter、Escape、控制组合等保守视为可能改动状态，需单独批准。Full 遵循已有完全访问选择；直接可识别的红线命令文字仍需批准。按键在任意程序中的业务含义不能由通用终端层可靠推断，不能将“成功写入”描述为“只读操作已验证”。审批界面展示目标、目的和输入，不允许将其改成 shell 命令或切换到独立通道。

## 记录和界面

复用统一工具卡片，读屏结果显示等宽行、光标/尺寸/终端信息，原始样式数据随日志保留。读取、输入和等待分别展示「已读取」「已发送」「条件已满足」「等待超时」「画面已变化」「已接管」，超时不因工具正常返回而显示绿色完成。成功返回的连续终端工具可合成一个过程卡片；只合并同一轮、同一代理和同一终端，中间已完成的思考摘要保留原顺序。文本回复、用户消息、目标变化、其他工具、错误、超时、接管和释放构成边界；活跃工具与审批仍单独显示。展开后可逐步查看完整内容。聚合仅影响展示，不改写历史、不重新执行旧工具。终端上方提供操作状态与接管/恢复入口。旧历史回放不自动重发按键，也不恢复旧控制权。需要用户决策时使用 ask_user。

## 验证

覆盖三种模型协议、主/子代理身份、拒绝审批、审批中断线、控制竞争、手动接管、过期/变化画面、区域忽略动态指标、尺寸变化、App Cursor、括号粘贴、宽字符与高亮、超时和停止。windowless GPUI 模型测试通过真实 PTY 驱动 Vim 编辑临时文件、less 搜索和退出；不使用用户终端或文件。原生 UI 样本 `proto:ai-terminal-interaction` 为惰性菜单后端，无网络和 shell，用于检查接管入口及屏幕结果显示。新增测试覆盖鼠标模式、完整手势、区域边界、创建审批拒绝及连接变化、主/子共享生命周期、三协议创建与管理、本机忽略 HUP 的进程组终止，以及进程内 SSH 服务器上的独立 PTY exec 和取消清理。真实 Vim 开启鼠标后完成点击和编辑。原生 UI 样本 `proto:ai-independent-terminal` 在临时数据目录运行本机 cat，用于查看、收起、重开、停止、关闭验证；运行样本时使用 SHELL=/bin/sh。真实远端 SSH 配合模型 API 的组合行为仍需实际环境验证。

独立 PTY 随应用生命周期存在，不是 tmux/守护进程托管。主动脱离会话的 daemon、nohup/setsid 进程不属于可恢复交互终端的保证范围；SSH 的退出行为还取决于服务端 PTY/channel 关闭处理。

本轮回归覆盖动态指标与菜单切换、裁剪标题仍检查整屏、明确的前置条件、同区域基准比较与缓存淘汰、输出延迟/无输出/目标不满足时仅发送一次、用户打断、三协议和子代理参数传递、状态映射和聚合边界。原生菜单样本同时展示正常过程与超时，验证深浅主题、展开/收起与详情。没有自动操作用户正在运行的 musicfox，也没有通过真实模型重跑歌曲播放任务。
