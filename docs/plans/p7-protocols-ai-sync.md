## 技术决定（已定，不要改动）

| 项 | 决定 |
|---|---|
| 主机类型 | 主机编辑器的协议分段：SSH / Mosh / Telnet / 串口。Telnet、串口、本机会话只有"终端"视图，文件、端口转发、监控三个视图禁用，提示"串口 / Telnet 会话不支持此面板"（原型如此）。Mosh 主机的这三个视图仍可用，走单独的 SSH 连接 |
| Telnet | 自己实现客户端（RFC 854），协商 ECHO、SGA、TTYPE（发送 `xterm-256color`）、NAWS（窗口大小，随窗格变化更新）。IAC 双向转义。主机编辑器提示"Telnet 以明文传输账号与数据，仅建议用于内网设备"，会话底栏显示"Telnet 明文"。**自动登录**：保存了密码时，连接后 10 秒内遇到 `login:` / `Password:` 提示才自动填写，各一次；超时或提示不匹配就交给用户手动输入 |
| 串口 | 用 `serialport` crate。主机编辑器列出本机串口设备（路径 + USB 描述，如"Silicon Labs CP2102"）；波特率 9600 / 115200 / 460800 / 921600 或自定义；默认 8N1、无流控，高级选项里可改。会话顶部是串口工具条（原型 `ser*`）：状态（● 已打开 / ○ 已关闭）、设备、波特率 ▾（打开状态下直接切换）、换行（CRLF / LF / CR）、HEX（以十六进制 + ASCII 显示收到的字节）、时间戳（每行前加 `[HH:MM:SS.mmm]`）、打开 / 关闭端口（关闭后可以用 esptool 等工具占用端口）。设备拔出时显示"设备已断开"，重新插入后自动打开。按原型，工具条另有 **DTR / RTS 开关与"复位 EN"**（ESP32 的复位 / 下载模式时序）；主机编辑器的串口页有：串口设备（路径 + USB 描述的下拉）、波特率分段、数据位 / 校验 / 停止位 / 发送换行、提示"打开端口时会拉高 DTR；ESP32 可在会话工具条中用 RTS/EN 复位进入下载模式。"、测试连接（打开并立即关闭端口） |
| Mosh | **不自己实现 Mosh 协议**。先用现有的 SSH 连接在远端运行 `mosh-server new -s -l LANG=…`，拿到端口与密钥；再在本机 PTY 中运行 `mosh-client`（通过环境变量 `MOSH_KEY` 传密钥，密钥不出现在命令行和日志里）。预测回显、网络漫游都由 mosh-client 负责。底栏显示"Mosh UDP <端口>"。本机没有 `mosh-client` 时提示安装方法（`brew install mosh`）；远端没有 `mosh-server` 时提示"远端未安装 mosh-server"；UDP 不通时如实报错 |
| AI 助手 | 工具栏"AI"打开右侧抽屉（原型 `ai.png`）。顶部"上下文：<会话> · 最近 40 行输出"，下方是建议问题、对话、输入框，底部注明"发送前会自动去掉 .env、私钥、密码等敏感内容"。回答里的命令逐条显示，可"复制"，或"插入"后进入 P6 的发送确认（危险命令照样标红）；**绝不自动执行**。终端里出现报错行（原型的 `AIERR` 规则）时，右上角浮出"解释报错"。上下文只包含**屏幕上已显示的文字**，先做脱敏再发送：私钥块、`KEY=VALUE` 中键名含 SECRET / TOKEN / PASSWORD / KEY 的值、常见云服务密钥格式、JWT、URL 里的用户名密码。脱敏规则做成表格测试。第一次使用时说明会把什么发给谁 |
| AI 接口 | 设置里新增"AI 助手"分区：服务商（Anthropic Claude，或 OpenAI 兼容接口填 Base URL）、模型、API Key（存入凭据存储，和 SSH 密码同一处）。**未配置时不发出任何请求**，抽屉里显示配置入口。流式显示回答，命令用结构化输出（Claude 用 tool use，兼容接口用 JSON 输出）。请求超时、限流、余额不足都给出中文说明 |
| 凭据存储 | 两种方式二选一：**系统钥匙串**（现状，默认）与**主密码加密本地库**。后者生成随机数据密钥加密每一条凭据（XChaCha20-Poly1305，每条随机 nonce），数据密钥再用主密码经 Argon2id 派生的密钥包裹；改主密码只需重新包裹数据密钥。切换方式时，现有凭据会在两边之间迁移，迁移完成才删除旧的一份。设置主密码时显示强度。内存里的密钥用完即清零（`zeroize`） |
| 解锁与锁定 | 需要凭据（连接、同步、AI）而凭据库处于锁定状态时，弹出解锁框。**闲置锁定**（默认 15 分钟）：清掉内存里的数据密钥，已建立的连接不受影响。**Touch ID 解锁**：把数据密钥存进钥匙串，读取前先通过 LocalAuthentication 验证指纹；关闭这一项时删除钥匙串里的这份 |
| 配置包 | "导出…"：选择要包含的内容（主机、分组、快捷命令、转发规则、凭据），用单独输入的导出口令加密（Argon2id + XChaCha20-Poly1305），文件带格式版本号，扩展名 `.smbundle`。"导入…"：先预览将新增 / 覆盖的条目，冲突时可选跳过 / 覆盖 / 另存一份 |
| 同步 | **只做 WebDAV**（如坚果云）；原型里的"Git 仓库同步"显示为"后续版本提供"。**同步必须先启用主密码加密本地库**：同步文件整体用凭据库的密钥加密，服务器上只有密文。同步内容：主机、分组、标签、跳板、快捷命令、转发规则、凭据（加密），以及一部分设置；命令历史、录制、日志不同步。按条目合并：记录每条的修改时间与设备，两边都改过同一条时进入冲突处理（原型 `syncDlg`：显示两边差异，保留本机 / 使用远端）；删除用墓碑记录。上传用 ETag（`If-Match`）防止覆盖别人刚上传的版本，失败时重新拉取、合并再上传 |
| 同步状态 | 侧边栏底部按原型显示："已同步 · WebDAV · N 分钟前" / "正在同步…" / "同步冲突 · N 项待处理" / "同步失败 · <原因>" / "本地配置 · 未开启同步"。点击时立即同步，冲突时打开冲突处理。同时提供自动同步（启动时、修改后、每 N 分钟）的开关 |
| 新依赖（我在每个里程碑开始前加好并下载，实现者在沙箱里无法联网） | `serialport`、`chacha20poly1305`、`reqwest`（只开 rustls、json、stream）、LocalAuthentication 的 objc2 绑定（与现有 `objc2` 版本匹配）。已在锁文件里的：`argon2`、`zeroize`、`quick-xml`、`security-framework`、`serde_json` |
| 不记录敏感内容 | 日志里不出现密码、密钥、API Key、主密码、AI 对话内容和同步内容 |

### M1：Telnet 与串口
- **做什么**：协议层（`crates/shellmate-telnet`、`crates/shellmate-serial`，都不依赖 gpui），主机编辑器的协议分段与对应字段，串口工具条，会话底栏信息，限制视图。
- **测试**

  - 串口：用 PTY 对模拟串口设备，覆盖 HEX、时间戳、换行切换、波特率切换、设备消失后自动重开。

### M2：Mosh
- **做什么**：经 SSH 启动 `mosh-server`；本机 PTY 中运行 `mosh-client`；Mosh 主机仍可使用文件、转发、监控；各种缺失或失败的说明。

  - 真实环境：测试机上 `apt install mosh`，本机需要 `mosh-client`（见文末问题）。

### M3：主密码加密本地库、Touch ID、闲置锁定、配置包导出 / 导入

  - `.smbundle` 导出 / 导入与预览。
- **测试**

## M1 review 结论（2026-11-16，通过）

提交：M1（本节之前的一个提交，含两轮修复）。

- Telnet：自己实现的客户端，对 GNU inetutils telnetd 2.5 的开场协商（WILL AUTHENTICATION / ENCRYPT → DONT；DO TTYPE → WILL；DO TSPEED / XDISPLOC / NEW-ENVIRON / ENVIRON → WONT）有逐字节测试。自动登录的 10 秒窗口从收到服务器第一个字节算起，总上限 30 秒（真实 telnetd 会先反查客户端域名，可能延迟 10 秒才出第一个字节）。
- 真实服务器：测试机 `shellmate-mon` 装了 inetutils-telnetd（经 inetutils-inetd，平时停用，只在测试时启动），并在 `/etc/hosts` 加了 Mac 的 IP 以避开反查延迟。e2e（`cargo test -p shellmate-telnet --test e2e -- --ignored`，需 `SHELLMATE_TELNET_PASSWORD`）5/5 连续两次通过：自动登录只填一次、`stty size` 随窗口大小变化（30 100 → 40 132）、命令往返、密码错误不自动重试、`exit` 后服务器关闭。
- 串口：PTY 模拟设备覆盖读写、关闭重开、设备消失与重现；macOS 的 PTY 不支持真实的波特率与 DTR/RTS，硬件相关项目写进 `docs/manual-tests.md`（S1–S12），等用户有 ESP32 等设备再测。
- 主机库升到 **schema v6**（串口参数、Telnet 端口；v5 程序打不开 v6 库）。
- 与原型的对比：串口会话约 1.9%、Telnet 会话约 1.2%、新建串口连接 2.8–5.0%（字段值已改为左对齐）。接受的差异：HEX 显示为完整的"偏移 + 十六进制 + ASCII"（原型是截断的十六进制）；新建 Telnet 连接多了密码与"存入钥匙串"两行（自动登录需要）；"复位 EN"为菜单，附"下载模式"；串口会话里原型的"AI 解释这个报错"属于 M5。
- 复跑（沙箱外）：clippy 零警告；`cargo test --workspace` 1143 通过；e2e SSH 8/8、SFTP 17/17、forward 7/7。

## M2 review 结论（2026-11-16，通过）

- Mosh 不自己实现协议：经现有 SSH 连接启动 `mosh-server new -s -c 256 -l LANG=<UTF-8 locale>`，本机 PTY 中运行 `mosh-client <SSH 实际到达的 IP> <端口>`，`MOSH_KEY` 只经环境变量，不进命令行、日志、录制与历史。
- 踩到的坑：mosh-client 所在的 PTY 窗口为 0×0 时会立即退出（"Error: vector"，并误报连接失败）；实现先设好窗口大小再启动，有回归测试。
- 跳板机：Mosh 需要直连 UDP，配置了跳板机时拒绝并提供"以 SSH 打开"。失败清理：客户端启动失败、立即退出、启动被放弃或标签关闭时，按 pid（先核对进程名）结束服务器上的 mosh-server，不做按用户的批量结束。
- 文件 / 转发 / 监控继续走 SSH 连接；SSH 断线重连不影响 mosh 终端。底栏"Mosh UDP <端口> · 预测回显 自适应"，不显示原型里的延迟数字（mosh-client 不提供）。
- 顺带修复：主机编辑器内容超高时底部按钮被裁掉。现在对话框标题与底栏固定、表单单独滚动，聚焦的输入框会滚进可见区域；设置、记录、编辑器对话框同样处理。在 1440×900 与 1100×700 下截图确认。
- 环境：按用户同意在本机 `brew install mosh`（1.4.0），测试机装了 mosh-server。
- 复跑（沙箱外）：clippy 零警告；`cargo test --workspace` 1159 通过；真实 Mosh e2e 2/2（`stty size` 30 100 → 40 132、`mosh-42`、退出后服务器无残留、客户端立即失败时清理）；SSH 10/10、SFTP 17/17、forward 7/7。

需要用户手测（写入 `docs/manual-tests.md`）：真实网络切换 / 合盖睡眠后 Mosh 会话不断。
