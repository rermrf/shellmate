# 通用用户提问

`ask_user` 是主代理和子代理共享的交互工具，不依赖终端类型或命令审批模式。每次 1–3 个问题，每题 0–4 个选项；支持单选、多选和自定义文字。无预选，不自动提交，无等待超时推定答案。

## 运行和协议

提问调用立即登记为带唯一 request_id 的完整工具结果 `pending`，这只表示问题已发出。程序随后按 mode 调度：`wait` 暂停发问 Agent，`async` 可继续无关工作；如果本轮已无工作，保持等待，不轮询模型、不占模型请求名额。答案是关联 request_id 的独立用户事件，不修改原工具结果；三种协议都按普通工具调用及后续用户反馈传输。等待期间普通追加消息可更新任务方向，明确回答、跳过和取消分别记录。

回答在保存成功后进入原任务输入队列，一次投递。重复提交失败，答案输入不可当成普通排队消息编辑/撤回；需要修订时另发用户消息。答案会清除当前未执行的计划步骤，让模型根据反馈重新决策。提问不替代命令审批，Full 模式也不会替用户回答。

## 界面和恢复

使用统一工具卡片外壳，待回答时展开选项及文字输入，提交后收起为问题与答案。主输入框始终可用。子代理问题在主对话显示轻量提醒，进入子代理页面回答；对话列表显示待回答状态。

问题、答案和输入队列一起持久化；填写中的选项与文字在停止输入约 350 ms 后保存。子代理检查点合并已提交答案，旧检查点不能覆盖刚提交的答复。重启后不自动执行任务，用户回答或继续时恢复；停止任务不替用户取消问题或选择答案。关闭/删除对话遵循既有生命周期，不恢复已删除的任务。

## 验证

模拟 Chat Completions、Responses、Anthropic 的工具调用与回答回传；等待释放模型名额、异步继续、停止/转向、保存失败不投递、重复提交、主任务并行、子代理停止后恢复、检查点写入竞态、草稿恢复。原生场景：`ai-question`、`ai-question-async`、`ai-question-child`、`ai-question-restored`。真实服务端是否主动选用工具依赖模型，不以模拟测试代替真实 API 联调。
