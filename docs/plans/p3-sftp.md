# P3：文件（SFTP）与内置编辑器 实施计划

目标：在 P2（SSH 会话、重连、连接共享）基础上，做出原型中的**文件面板**：浏览远端目录、上传 / 下载（含文件夹、断点续传）、
新建 / 重命名 / 删除 / 改权限，以及**内置编辑器**（语法高亮、原子写回、冲突检测）。

端口转发 / 监控仍属于 P4 / P5，继续禁用。本机会话的"文件"保持禁用，提示"本机文件请使用 Finder"（与原型一致）。

原型参考：`docs/Shellmate 原型.html` 中的文件视图（`isFiles`）、`fileAct` / `handleFiles` / `queueUp` / 上传冲突（`isUpc`）/
传输队列（`transfers`）/ 编辑器（`isEditor`、`edMeta`、`edAsk*`）。截图：文件视图、编辑器。

## 技术决定（已定，不要改动）

| 项 | 决定 |
|---|---|
| SFTP 库 | `russh-sftp` 3.0.x（russh 官方配套，纯 Rust）。客户端在已有 `Connection` 上开 `sftp` 子系统通道，`SftpSession::new(channel.into_stream())` |
| 新 crate | `crates/shellmate-sftp`：SFTP 会话、目录 / 文件操作、文本文件读写（原子保存 + 冲突检测）、传输引擎。**不依赖 gpui**。`shellmate-ssh` 只新增一个公开方法用于在连接上开子系统通道 |
| 会话归属 | 每条连接（P2 的 `ConnGroup`）最多一个 `SftpSession`，首次打开文件面板时懒加载，面板浏览与传输共用；连接重连后重新打开。复制出来的标签共享同一个会话与传输队列，但每个标签有自己的当前目录 |
| 传输引擎 | 运行在 SSH 的 tokio 运行时上，进度经 `async-channel` 回到 gpui。每条连接最多同时进行 **2** 个传输，其余排队 |
| 下载位置 | `~/Downloads`。下载中写入 `<名称>.shellmate-download`，完成后改名；重名时追加 ` (1)`、` (2)`… |
| 上传写法 | 写到同目录的 `.<名称>.shellmate-upload`，完成后替换为目标（见"原子替换"）。断点续传：本地按 `.shellmate-download` 的长度续，远端按 `.shellmate-upload` 的长度续 |
| 原子替换 | 服务器支持 `posix-rename@openssh.com` 时用它；否则：原文件改名为 `.<名称>.shellmate-bak` → 临时文件改为目标名 → 删除备份（中途失败要把原文件改回）。覆盖已有文件时**保留原文件的权限**；新文件采用本地文件的权限位（`& 0o777`）。三条安全规则：① 替换前先以只写方式探测原文件（不创建、不截断），不可写就报「权限不足」且什么都不写（改名替换不检查文件自身权限，否则会绕过只读文件）；② 属主保不住就**原地写入**：写完临时文件后尝试 chown 并 `fstat` 核对，原文件的 uid / gid 已知而临时文件不一致（非 root 无法改属主，如组可写但属主是别人的文件）时丢弃临时文件、改为原地写入（`WriteMode::InPlace(KeepOwner)`，状态提示「已直接写回（保留属主）」；同组改组仍成功，常见情况保持原子）；③ 临时文件一律**独占创建**（CREATE\|EXCLUDE，不截断）：名字已被占用就先 unlink（不跟随链接）再重试一次，unlink 被拒（如粘滞目录里别人的文件）按目录不可写处理，防止预置的符号链接把写入引到别的文件（上传临时文件同样遵守）。目标是悬空符号链接时沿链接逐跳（相对该链接所在目录，最多 16 跳）在最终位置创建文件，链接保持为链接 |
| 目录不可写 | 编辑器保存或覆盖上传时，若同目录无法创建临时文件（权限不足，或临时名被占用且无法清除），退回为原地截断写入，并在状态里注明"已直接写回（目录不可写）"（`WriteMode::InPlace(DirNotWritable)`） |
| 符号链接 | 列表中标出并显示目标；双击按目标类型处理；编辑符号链接时写回**解析后的目标文件**（不能把链接替换成普通文件）；递归传输中跳过符号链接并在完成后报告跳过数量 |
| 跟随终端目录 | 解析终端输出中的 OSC 7（`ESC ] 7 ; file://host/path BEL/ST`，路径做百分号解码），由 `shellmate-term` 发出 `TerminalEvent::CwdChanged`。远端 shell 默认不发 OSC 7：开关旁显示"终端未上报目录"，并提供 bash / zsh 的启用片段（可复制）。从未收到时，面板打开在用户主目录（`canonicalize(".")`） |
| 编辑器 | gpui-component 的代码编辑器输入框（带行号）。高亮优先用 gpui-kit 的 `syntect` 特性；若不可用或 target 增长超过 1 GB，改用少数 tree-sitter 语言（bash、yaml、json、toml、markdown），其余纯文本。只打开 ≤ 5 MB、UTF-8 的文本（含 BOM 时保留）；保留换行风格（LF / CRLF） |
| 时间与大小 | 大小：`612 B`、`2.3 KB`、`1.8 MB`、`1.21 GB`（与原型 `fmtSize` 一致）。修改时间用本地时区：今年 `11-12 08:55`，往年 `2025-11-12` |

## 里程碑（每个里程碑单独提交，完成后停下等待 review）

### M1：SFTP 核心（无 UI）
- `shellmate-ssh`：在 `Connection` 上开子系统通道（用于 `sftp`）。
- `shellmate-sftp`：
  - 打开会话、`canonicalize`、列目录：目录在前，名称按不区分大小写的自然顺序排列，显示隐藏文件；每项含类型、大小、修改时间、权限、属主（优先用 `longname` 中的用户名 / 组名，否则 `uid:gid`）、符号链接目标。
  - `stat`、新建目录、重命名（目标已存在时报错，不覆盖）、删除（目录递归）、修改权限（`setstat`）。
  - 文本文件：读取（大小上限、二进制 / 非 UTF-8 检测、换行风格检测）与保存（原子替换、保留权限、冲突检测：打开时记下大小与修改时间，保存前再 `stat`，不一致则返回冲突，附远端当前内容以便显示差异）。
  - 错误转成清晰的中文（权限不足、不存在、已存在、不是目录、连接已断开等）。
- `shellmate-term`：OSC 7 解析与 `CwdChanged` 事件（数据可能跨读块分段，要能拼接）。
- **测试**：
  - 进程内：在 M1 的 russh 测试服务器上加 `sftp` 子系统，用 `russh_sftp::server` 实现一个以临时目录为根的处理器；分别覆盖服务器**支持与不支持** `posix-rename@openssh.com` 两种情况。覆盖：列目录排序与属性、增删改、递归删除、权限修改、符号链接、文本读取的各种拒绝情况、原子保存（含失败回滚）、冲突检测、目录不可写时的退回写法。
  - OSC 7：BEL / ST 结尾、分段到达、百分号编码、中文路径、无效序列忽略。
  - 真实服务器（`#[ignore]`）：列目录、保存保留权限、编辑符号链接、无权限目录（如 `/root`）。

### M2：传输引擎（无 UI）
- 上传 / 下载单个文件与整个目录（一项队列条目对应一次选择；先遍历得出总大小与文件数，进度按字节聚合）。
- 状态：排队中 / 进行中（速度按最近几秒平滑）/ 已暂停 / 已完成 / 失败（附原因）/ 已取消。
- 暂停与续传（按已写入长度续传）；取消时删除临时文件；同名处理：跳过 / 保留两者（追加 ` (1)`）/ 覆盖，一次选择应用到同批所有文件。
- 连接断开：进行中的传输变为"已暂停 · 连接断开"，连接自动重连成功后**自动续传**。
- 下载完成后把本地文件修改时间设为远端时间；上传完成后把远端修改时间设为本地时间。
- 吞吐：读写使用足够大的块并允许多个请求在途；在真实服务器（本机回环）上测出上传 / 下载速度写进报告，低于 10 MB/s 要先查原因。
- **测试**：进程内服务器上覆盖上述全部状态转换、目录传输、续传后内容一致（校验和）、取消清理、同名三种处理、并发上限 2、断线后续传；真实服务器上传 / 下载 ≥ 50 MB 文件并比对校验和，传输中途在容器内杀掉会话后续传成功。

### M3：文件面板
- 启用 SSH 会话的"文件"视图，布局按原型：
  - 顶部：面包屑（点击跳转）、"跟随终端目录 · OSC 7"开关、新建文件夹、下载、上传（主按钮）、刷新。
  - 列表（虚拟滚动，万级条目不卡）：名称 / 大小 / 修改时间 / 权限；`..` 返回上级；单击选中，双击进入目录或用编辑器打开文件；底部提示"拖拽文件到此处上传 · 双击进入目录或编辑文件 · 右键更多操作"。
  - 右键菜单：打开（或"用内置编辑器打开"）、下载、重命名（行内编辑）、复制路径、修改权限、删除（二次确认，目录注明递归删除）。新建文件夹后直接进入行内重命名。
  - 右侧详情：名称、类型、大小、修改时间、属主；权限 3×3 读 / 写 / 执行网格 + 八进制与符号表示 + "应用 chmod"；文件显示"用内置编辑器打开"（M4 前可先禁用并提示）。
  - 底部传输队列：方向图标、名称、状态 / 速度、进度条、已传 / 总量、按钮（暂停 / 续传 / 取消 / 打开——打开即在 Finder 中显示）、"N 个进行中 · M 个完成"、"清除已完成"。
- 上传：上传按钮打开 macOS 文件选择（可多选，可选文件夹）；从 Finder 拖入文件 / 文件夹（拖入时高亮列表区域）；同名时弹出原型的"N 个文件已存在"对话框（跳过 / 保留两者 / 覆盖）。
- 键盘：↑ / ↓ 选择、回车打开、⌘↑ 上级目录、⌘⌫ 删除（确认）。焦点在列表时这些按键不能进终端。
- 状态：加载中、空目录、错误（如权限不足，显示原因与"返回上级"）；连接断开时面板显示"连接已断开，重连后自动刷新"，重连后刷新。
- 自身操作完成后自动刷新当前目录；跟随开启时，终端目录变化后跟着切换（手动导航会关闭跟随，与原型一致）。
- 顺带修复 P2 遗留：即将自动重连时，断线那一行不再带"按回车重新连接"。

### M4：内置编辑器
- 按原型做成大对话框：标题行（文件名、语言徽标、`主机名:路径`、状态、"关闭"、"保存并上传 ⌘S"）、带行号的编辑区、底栏 `N 行 · UTF-8 · LF` 与"保存时经 SFTP 原子写回（临时文件 + rename），保留原权限与属主"。
- 状态：`已与服务器同步` / `● 已修改，未上传` / `正在通过 SFTP 上传…` / `✓ 已上传 · 时:分:秒`；失败时显示原因，修改不丢。
- 冲突："远端文件已被修改"——"<文件> 在你打开之后于 HH:MM 被修改。直接上传会覆盖对方的改动。"，显示简短差异（原型中的 `@@ 第 n 行 @@` 片段），按钮：取消 / 载入远端版本 / 覆盖远端。
- 关闭时有未上传修改："有未上传的修改"——取消 / 放弃修改 / 上传并关闭。Esc 等同关闭。
- 拒绝打开时（二进制、非 UTF-8、> 5 MB）提示原因并建议下载后查看；提供"下载"按钮直接加入传输队列。
- 连接断开时保存失败要保留编辑内容，重连后可再次保存。
- **测试**：编辑状态机（干净 / 已修改 / 保存中 / 已保存 / 冲突 / 失败）不依赖 gpui 单测；差异片段生成单测；真实服务器上保存后权限与属主不变、换行风格不变。

## 通用要求
- 沿用 P2 的通用要求（中文文案参考原型、不记录敏感信息、零警告、不用合成键鼠事件、只读截图、新增图标加入 `assets.rs` 与测试）。
- SFTP 路径一律按远端 POSIX 路径处理（不要用 `std::path::Path` 拼远端路径）。
- 删除、覆盖等破坏性操作必须二次确认或有明确的同名处理选择；测试中只在临时目录和 `shellmate-e2e` 容器里操作。
- 每个里程碑：`cargo build`、`cargo test --workspace`、`cargo clippy --workspace --all-targets` 零警告。

## M1 review 结论（2026-11-14，通过）

提交：`2cbe35b`（实现）、`cf44210`（review 修正）、`31ac99b`（e2e 临时目录名冲突）。

验证：`cargo test --workspace` 全过、clippy 零警告；真实服务器（OpenSSH 10.3，`shellmate-e2e`）上 SFTP e2e 11 项连续 3 轮全过，SSH e2e 8 项仍全过，容器内无残留。

确认的事实与取舍：
- `russh-sftp` 3.0.1 可用，但高层 `SftpSession` 不暴露服务器扩展、也发不了 `posix-rename`，所以建在 `RawSftpSession` 上（`init()` 拿扩展，`extended()` 发 posix-rename）。容器 OpenSSH 通告：`posix-rename`、`fsync`、`limits`、`lsetstat`、`copy-data`、`expand-path`、`hardlink`、`home-directory`、`statvfs`、`fstatvfs`、`users-groups-by-id`（SFTP v3）。
- 请求超时设为 30 秒（库默认 10 秒）。
- API：`save_text(.., expected: Option<Revision>)`，`None` 即"覆盖远端"；打开后被删除的文件返回"不存在"而不是悄悄重建。`Conflict.remote_text` 为 `Option`（远端可能已不是文本）。编辑器保存的临时名为 `.<名称>.shellmate-edit`，与上传的 `.shellmate-upload` 区分。
- OSC 7：alacritty 0.26 不处理 OSC 7，改为在 IO 线程上、送给解析器之前扫描字节流（只看不改，跨读块保持状态，只报告变化）。

review 修正（`cf44210`）：
1. 可写目录中的只读文件（如 0444）原先会被改名替换"写穿"——保存前先以只写方式探测原文件，不可写报"权限不足"、什么都不写（`ensure_writable`，M2 覆盖上传共用）。
2. 属主保不住时（非 root 编辑组可写、属主是别人的文件）原先会悄悄变成自己的文件——改为原地写入，`WriteMode::InPlace(KeepOwner)`；chown 放在最终 chmod 之前，避免清掉 setuid/setgid。
3. 临时文件改为独占创建（CREATE|EXCLUDE，不截断），防止预置的符号链接把写入引到别的文件；顺带修了退回原地写入时会删掉不是自己创建的临时名的问题。
4. "覆盖远端"时目标是悬空符号链接，原先会把链接替换成普通文件——改为沿链接逐跳在最终位置创建，链接保持为链接。

已知限制（接受）：
- SFTP v3 修改时间精度为 1 秒：同一秒内、大小不变的他人修改检测不到冲突。
- 混合换行的文件按多数风格处理：以 CRLF 为主时保存会把零星的 LF 行也写成 CRLF；以 LF 为主时文本中保留 `\r`。
- 非 UTF-8 的文件名有损解码（显示替换字符，对其操作会失败）。
- 大小写不敏感的服务器上，只改大小写的重命名会被"目标已存在"拒绝。

留给后续里程碑：
- M3：`SubsystemStream` 持有 `Connection`，`SftpSession` 必须随 `ConnGroup`（最后一个标签关闭）一起释放，否则连接不会关闭（P2 M4 修过同类泄漏）。
- M3：OSC 7 不区分主机——终端里再 ssh 到别的机器时，上报的目录可能在本机不存在；跟随时进入失败要显示错误并保留原列表，不能把面板弄空。
- M4：状态栏用 `InPlaceReason::label()` 显示"已直接写回（目录不可写 / 保留属主）"。

## M2 review 结论（2026-11-14，通过）

提交：`db97805`（实现）、`ddaf26e`（review 修正）。

验证：`cargo test --workspace` 全过、clippy 零警告；SFTP e2e 15 项连续 2 轮全过，SSH e2e 8 项全过，容器内无残留。本机回环到 `shellmate-e2e` 的吞吐：50 MB 单文件上传 172–180 MB/s、下载 115–120 MB/s；1000 个小文件上传约 2.0 s、下载约 0.8 s。真实服务器上传输中途杀掉该会话的 `internal-sftp` 进程后，换新会话 `set_session` 续传完成、校验和一致。

接受的偏离：
- 容器 sshd 用 `internal-sftp`，没有 `sftp-server` 进程；e2e 按该连接的会话 pid 只杀它自己的子进程。
- 目录不可写时覆盖上传按计划退回原地写入（非原子、续传从头开始），`TransferView::in_place_note()` 给出"N 个文件已直接写回（目录不可写）"。上传的属主只尽力保留，不像编辑器那样为保属主改原地写入（否则失去原子替换与续传）。
- 上传不做 fsync（小文件目录耗时减半，与 scp / sftp 一致）；编辑器保存仍 fsync。
- 在途窗口约 2 MB（8–32 个请求），保证暂停及时生效。
- 目标路径重叠的上传条目串行（会写同一个 `.shellmate-upload`），后者再进入"等待处理同名"。
- 子代理的提交署名为 `Co-Authored-By: Claude Sonnet 5.5`（如实标注实际作者）。

review 修正（`ddaf26e`）：
1. 上传续传可能留下空洞：服务器可能乱序执行写请求，断线时临时文件长度不等于连续写入的前缀——改为记录连续确认前缀（highwater），续传从 `min(临时文件长度, highwater)` 开始。
2. 会话停滞 / 被收走时原先会把文件判为失败并删掉临时文件：`Timeout` 视同会话丢失（`is_session_lost`）；已被 `set_session(None)` 收走后返回的任何错误都按断线处理；断线暂停不再等待在途请求，用户暂停的等待超时也只算暂停。
3. 新增 `TransferEvent::SessionLost`（每个会话代次最多一次）：SFTP 子系统死了而 SSH 连接可能还在时，由应用重开会话并 `set_session`。
4. 单文件下载报告真正落盘的路径（最后改名时可能换了名字），"在 Finder 中显示"指向正确文件。
5. 下载出错 / 断线路径先 flush 再丢弃文件句柄。
6. 每个条目最多保留 100 条失败明细，另计总数。

已知行为（接受）：
- 传输队列只在内存中，应用重启后不保留。
- 用户点"暂停"后立刻点"继续"，若任务已决定停下，条目仍会停在"已暂停"，需再点一次继续。
- 原地写回的覆盖上传若中途取消，目标文件会留下部分内容（用户已选择覆盖）。

留给 M3：
- `ConnGroup` 持有该连接的 `SftpSession`（懒打开）与 `TransferQueue`：断线时 `set_session(None)`，重连成功后重开会话再 `set_session`；收到 `SessionLost` 且连接仍在时重开；最后一个标签关闭时 `shutdown()` 并释放会话。
