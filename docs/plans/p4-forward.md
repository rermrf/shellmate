# P4：端口转发 实施计划

目标：在 P2（SSH 连接、重连、连接共享）与 P3 的基础上，做出原型中的**端口转发**面板：本地转发（-L）、远程转发（-R）、动态 SOCKS5（-D），规则按主机保存，连接建立 / 重连后自动恢复，显示连接数与流量。

监控仍属于 P5，继续禁用。本机会话的"端口转发"保持禁用，提示"本机会话不需要端口转发"（与原型一致）。原型中"监控 → 容器 → 一键转发端口"属于 P5，届时复用本阶段的接口。

原型参考：`docs/Shellmate 原型.html` 中的 `isFwd`、`rules`、`rf*`（新建规则表单）、`fwdRunning`、`retry`、`remove`。截图：端口转发视图。

## 技术决定（已定，不要改动）

| 项 | 决定 |
|---|---|
| 新 crate | `crates/shellmate-forward`：规则模型、地址解析、监听与转发、SOCKS5、统计、生命周期。**不依赖 gpui**，运行在 SSH 的 tokio 运行时上，状态经 `async-channel` 回到 gpui |
| `shellmate-ssh` 新增 | `Connection::open_direct_tcpip(host, port, originator)` → 字节流（持有连接，丢弃即关通道）；`request_remote_forward(addr, port) -> 实际端口`、`cancel_remote_forward`；`ClientHandler` 按 (地址, 端口) 把服务器发来的 forwarded-tcpip 通道分发给登记者，没人登记的一律拒绝 |
| 规则归属 | 规则属于**已保存的主机**，存 SQLite 新表 `forward_rules`（id、host_id 级联删除、类型 L/R/D、名称、监听地址与端口、目标地址与端口（D 为空）、是否启用、排序）。临时连接（未保存的主机）的规则只在内存里，面板注明"临时连接的规则不会保存" |
| 运行归属 | 每条连接（`ConnGroup`）一个 `Forwarder`，同一主机的所有标签共用、面板显示同一份规则与状态。`Forwarder` 只持有 `WeakConnection`；每个转发中的连接持有 `Connection` 克隆。最后一个标签关闭时 `shutdown()`：关闭监听、中止所有转发任务——连接必须随之关闭（P2 M4 / P3 都出过同类泄漏，要有测试） |
| 自动启动 | 已启用的规则在连接建立后自动启动；开关即时启停并保存"是否启用" |
| 断线与重连 | -L / -D：断线期间**保留本地监听**（端口不被别人占走），新来的连接立即关闭，状态"等待重连"；已建立的连接随断线结束。-R：重连成功后重新向服务器申请。重连成功后全部恢复为运行中 |
| 关闭最后一个标签 | 若有规则正在运行，先确认："关闭后 N 条端口转发会停止（当前 M 个连接会断开）"——取消 / 关闭 |
| 地址写法 | 监听：`3306`（= `127.0.0.1:3306`）、`127.0.0.1:3306`、`[::1]:3306`、`0.0.0.0:3306`；目标：`host:port`、`[v6]:port`。端口 1–65535（-R 监听端口可为 0 = 由服务器分配，显示实际端口）。错误用中文说明 |
| 监听非本机地址 | 本地监听 `0.0.0.0` / `::` / 局域网地址时显示提醒"局域网内其他设备也能访问此端口"；-D 监听非本机地址额外提醒"这相当于开放代理"。默认始终是 `127.0.0.1` |
| 端口被占用 | 状态"本地端口 N 已被占用"，按钮"换用 M 重试"：M 从 N+10000 起（超出 65535 则从 N+1 起）找第一个空闲端口；点了就改写规则并启动 |
| -R 监听地址 | 缺省为远端 `127.0.0.1`。填 `0.0.0.0` 时提示"服务器未开启 GatewayPorts 时只能在远端本机访问"。服务器拒绝时显示"服务器拒绝了远程转发（可能禁用了 AllowTcpForwarding）" |
| SOCKS5 | 只做无认证、CONNECT；地址类型 IPv4 / IPv6 / 域名，**域名交给远端解析**（直接作为 direct-tcpip 的目标）；BIND / UDP 返回"不支持的命令"；SOCKS4 请求直接关闭。通道打开失败按原因映射回复码（拒绝连接 0x05、被禁止 0x02、不可达 0x04、其他 0x01） |
| 统计 | 每条规则：活动连接数、自启动以来的 ↓ 接收 / ↑ 发送字节（↓ 为从 SSH 一侧收到的）。最多每秒更新一次。大小格式与 P3 相同 |
| 导入 `~/.ssh/config` | 解析 `LocalForward` / `RemoteForward` / `DynamicForward`，导入主机时一并生成规则（启用，名称取"-L 3306"这类） |
| 不记录内容 | 日志里不出现转发的数据，只记规则、地址与错误 |

## 里程碑（每个里程碑单独提交，完成后停下等待 review）

### M1：转发引擎（无 UI）
- `shellmate-ssh`：上面三个新接口 + forwarded-tcpip 分发。
- `shellmate-forward`：规则与地址解析（单测覆盖各种写法与报错）；-L / -D / -R 运行时；SOCKS5；统计；`Forwarder` 生命周期：启动 / 停止单条规则、`connection_lost` / `connection_restored`、`shutdown`；端口被占用的错误与建议端口。
- **测试**：
  - 进程内：russh 测试服务器加上 direct-tcpip（连到测试里的回显服务）与 tcpip-forward / forwarded-tcpip。覆盖：-L 往返、多个并发连接、大流量校验和；-D 的 IPv4 / IPv6 / 域名 / 不支持的命令 / 失败回复码；-R 往返与端口 0；断线后本地端口仍被占着、新连接被立即关闭、恢复后可用、-R 重新申请；端口被占用与建议端口；`shutdown` 后连接关闭（无泄漏）。
  - 真实服务器（`#[ignore]`，`shellmate-e2e`）：-L 到容器内 `127.0.0.1:2222`（能读到 SSH 版本行即通）；-D 经 SOCKS5 到同一地址；-R：远端 `127.0.0.1:<端口>` 连回本机的测试回显服务（在容器里用 `docker exec` 发起连接）。-L 吞吐（≥ 100 MB，校验和）写进报告。

### M2：保存、接线与面板
- `shellmate-store`：`forward_rules` 表（迁移 + 测试）与增删改查；`~/.ssh/config` 导入转发。
- 接线：`ConnGroup` 持有 `Forwarder`；连接建立 / 断线 / 重连 / 最后一个标签关闭时通知它；关闭确认。
- 面板（按原型）：
  - 顶部卡片："N 条规则运行中"、"经由 <主机> 的 SSH 连接 · 断线重连后自动恢复"、"新建规则"按钮。
  - 新建表单（展开在顶部卡片下）：类型分段（-L 本地 / -R 远程 / -D 动态）、规则名称、监听地址（占位随类型："本地监听 127.0.0.1:5432" / "远端监听 0.0.0.0:9000"）、→、目标地址（"目标 db.internal:5432" / "转发到本机 localhost:3000"；-D 显示"SOCKS5 代理，目标由客户端决定"）、"添加并启动"；输入错误就地提示。
  - 规则卡片：类型方块（-L / -R / -D，各自配色）、名称 + 类型名、`监听 → 目标`（等宽）、状态（圆点 + "运行中 · N 个连接" / "已停用" / "等待重连" / 错误文字）、流量"↓ x · ↑ y"、错误时的重试按钮（如"换用 18080 重试"）、开关、删除（确认"删除规则「名称」？"，有活动连接时注明会断开）。
  - 空状态：没有规则时说明三种转发各自的用途，并给"新建规则"。
- 顺带修 P3 遗留：拒绝打开对话框中"请下载后查看"的折行；差异片段加一行图例"- 你的版本 · + 远端版本"。
- **测试**：存储与导入单测；面板模型（不依赖 gpui）单测：表单校验、状态文案、按钮、汇总；真实 app 截图（浅色 / 深色）对照原型；真实服务器上：-L 规则开关、断线重连后恢复（杀掉该会话的 sshd 子进程）、关闭最后一个标签的确认。

## 通用要求
