# 命令输出查看与折叠：实施计划

状态：已实施，验收记录见文末。2026-11-25 根据已确认的交互方案规划，代码基线 `7920416`。

## 1. 目标和范围

用户直接查看、展开和复制命令输出。输出 UUID、落盘路径和模型读取工具留在内部；用户展开日志由应用在本机读取，不发起模型请求，不增加模型上下文。

本次覆盖普通命令、子代理内部的命令、运行中/转后台的命令和历史对话。继续使用现有 Flyme 12 步骤卡片。子代理报告保留 Markdown 展示和“复制报告”，其执行记录使用共同的输出查看组件。

本次不改命令执行目标选择、审批策略、模型工具定义、上下文预算或压缩策略；不调整现有 30 天清理、随对话删除、单条日志 64 MiB 首尾保留及 5 GB 终止规则。“全部”指仍然完整保留的输出；存储时已经丢弃的内容必须明确提示。

不新增设置项、独立日志管理页面、日志导出或搜索功能。仅支持阅读操作的历史对话同样允许展开和复制。

## 2. 参考产品与当前缺口

参考依据：

- [Claude Code 全屏模式](https://code.claude.com/docs/en/fullscreen#use-the-mouse)：点击折叠工具结果展开，再次点击收起；支持选择复制；向上滚动暂停自动跟随。
- [Claude Code 输出限制](https://code.claude.com/docs/en/tools-reference#output-limits)：给模型的内联输出、落盘文件和界面展开不是同一层；大输出本身也有保留边界。
- [Codex CLI 0.172.0 输出渲染](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/exec_cell/render.rs)：简短预览与详细 transcript 分开，省略内容有查看入口。
- [Codex 实时输出缓冲](https://github.com/openai/codex/blob/ebd0765aafa255d63ebf690ebdffe0164dc14a0c/codex-rs/tui/src/exec_cell/live_output.rs)：展开仍受已保留内容约束，不能恢复存储层丢弃的输出。

基线代码的缺口：

| 位置 | 现状 | 本次处理 |
|---|---|---|
| `shellmate/src/ai/output_view.rs` | 从工具结果文本中解析并显示“完整输出 … 已保存 · UUID” | 用户展示与模型结果分离，使用结构化输出来源 |
| `shellmate/src/ai/agent_ui.rs::step_card` | 展开仅把显示上限从 8 行提高到 320 px；复制 `output.clone()` | 展开和复制从完整日志取数据；短预览也可以有全文入口 |
| `shellmate/src/ai/agent_ui.rs` | `readonly` 会隐藏输出展开、复制 | 历史阅读可用，执行类操作继续受原权限限制 |
| `shellmate/src/ai/subagent_ui.rs` | 子步骤同步读取完整文件，缓存字符串，和普通步骤行为不同 | 共享异步读取与输出视图，保留子步骤逐条展开的布局 |
| `shellmate/src/ai/tasks.rs` | 已有任务、输出 ID、运行状态、落盘能力 | 给本地查看提供查询接口，不借道模型的 `read_output` |
| `shellmate-core/src/ai_output.rs` | 运行中使用环形尾部，结束时线性化；存在 `.meta` 和保留边界 | 使用理解这些格式的读取器，不能直接把活动 `.log` 当普通顺序文件读取 |

## 3. 确定的交互

### 3.1 普通输出

| 状态 | 内容与动作 |
|---|---|
| 无输出 | 显示“（无输出）”，不显示无意义的展开和复制 |
| 完整且不超过 8 行 | 直接显示全部，动作“复制输出” |
| 超过 8 行，默认折叠 | 最多 8 行预览：前 3 行、1 行省略提示、后 4 行；动作“展开输出”“复制全部” |
| 预览不完整，但显示不足 8 行 | 仍提供“展开输出”，不能因为高度未溢出而隐藏入口 |
| 已展开 | 显示可滚动的完整保留内容，动作“收起”“复制全部”；不要求用户反复点“加载更多” |
| 首次读取 | 保留已有预览，轻量提示“正在读取输出…”；加载不阻塞对话输入和停止操作 |
| 日志已清理 | 保留已有预览，提示“完整输出已清理，仅保留预览”；动作“复制预览” |
| 存储时已截断 | 提示“输出过大，部分内容未保留”；明确标出首尾之间的缺口；动作“复制已保留内容” |
| 读取失败 | 保留已有预览，提示“暂时无法读取完整输出”，提供“重试”“复制预览” |
| 老记录只有内联内容 | 展示已有文本；已知为截断预览时说明限制，完整性无法确认时不声称“完整” |

只有行数已知时才显示“共 N 行”或“省略 N 行”；未完成索引、日志仍增长或中间已丢失时不编造精确行数。普通折叠和存储缺失使用不同文案。

命令区域保持现有独立的展开/复制。输出复制得到可读日志正文，保留换行、顺序和可识别的标准错误标记，不包含 Shellmate 添加的输出 ID、任务说明或工具包装。日志正文自己打印的 UUID、路径或“输出 id”字样必须保留。

### 3.2 运行中与后台命令

- 复用当前任务注册表，提供“查看输出”入口；原步骤卡片、任务栏和 `/tasks` 指向同一份输出视图，不创建新的 AI 消息或重复任务。
- 尚未分配输出文件时显示“等待输出”，收到输出引用后再读取；等待审批的命令不提前执行或创建假日志。
- 用户打开输出后刷新增量，初始复用现有 1 秒更新节奏；隐藏或关闭的查看区域不持续读取全文。
- 当前位于底部时跟随新增输出；用户向上滚动或开始选择时暂停跟随，显示“回到底部”，点击或滚回底部恢复。
- 运行中复制以点击时刻为快照，标签“复制当前输出”，完成提示不承诺包含之后产生的内容。
- 前台转后台、命令退出、失败、取消和断线后保留同一输出身份，保留用户的展开状态和阅读位置。任务状态直接取注册表，不重新推断退出码。

### 3.3 子代理与历史

- 子代理执行记录继续一次展开一条命令；展开行中的输出使用与普通步骤相同的数据读取、复制、缺失提示和滚动行为。
- 子代理的“报告”和“命令输出”分开：报告仍按 Markdown 渲染，命令输出保持等宽原文。
- 重新打开历史对话后无需恢复任务注册表或调用模型即可查看日志。
- 同一对话多个输出、不同子代理同名调用、不同对话的 `agent-1` 不共享状态或缓存。
- 清空/切换/删除对话时取消旧读取；迟到的读取结果不能写入新对话，也不能重新创建已删除的日志。

## 4. 界面规格

- 复用 `step_surface` 的 `card2` 底色、12 px 圆角、10 px 内边距和现有 8 px 间距；不用新颜色或新容器层级。
- 输出继续使用现有等宽字体、12.5 px 字号、18 px 行高。长行横向滚动，不自动折行改变命令日志的结构。
- 普通展开区域沿用 320 px 最大高度，短输出按实际内容高度；“展开”代表解除内容预览限制，不代表把整个对话撑成无限长卡片。
- 操作沿用现有右对齐文字按钮：24 px 高、12.5 px 字号、12 px 间隔；标签明确区分命令和输出。
- 移除“已保存 · UUID”一行，不用另一条路径或大小提示替代。可选行数与展开动作同一行。
- 完整性提示仅在清理、截断或读取异常时显示。普通折叠提示使用 `tx3`；异常沿用已有状态色。
- 鼠标选择、跨视口拖选自动滚动、横向滚动和复制沿用项目已有交互；虚拟化后必须覆盖跨页选择，不能退回只能复制屏幕内文字的行为。

## 5. 数据读取与组件设计

### 5.1 输出来源和状态

在应用层新增共同的输出描述和阅读状态，建议拆为 `ai/output_document.rs` 与 `ai/output_ui.rs`，让 `output_view.rs` 负责预览/文案的纯投影。

输出描述至少携带：会话 ID、所属步骤/子任务身份、输出 ID（可选）、已有预览、运行状态、完整性信息。使用 `Entry::Step.result.output_id` 或注册表的结构化字段映射卡片；不要把对话中的任意路径或 UUID 当作可读取文件。

历史卡片投影通过同一条 `Entry::Step` 建立身份映射，避免分别过滤日志和 UI 项后按索引拼接造成错配。正常日志不依赖从正文猜测输出 ID；旧格式兼容只在明确的工具结果包装范围内解析。

阅读状态包括：未加载、加载中、可读、已清理、失败，以及独立的“完整/保留首尾/完整性未知”标记。折叠状态、读取状态和存储完整性分开表示。

### 5.2 本地读取

- 在 `shellmate-core::ai_output` 增加面向界面的元数据与分页/快照读取接口，继续使用既有 ID 校验和按会话定位规则。
- 运行中的读取复用 `Spool` 或具备一致性保证的读取入口，正确重建环形输出的时间顺序；避免读到 `.log`、`.meta` 不匹配的中间状态。
- 返回“本次窗口没读完”和“源输出已经丢失部分内容”两个不同状态。当前单个 `Window.truncated` 不足以直接决定用户文案。
- 结束后的完整性来自可信元数据，不通过扫描日志里的“省略”字样判定。需要补充元数据时兼容已有文件；老文件无法确认完整性则明确降级，不能假定完整。
- 读取与文本清理在后台执行，不在 GPUI 的 `render` 或每秒刷新回调里同步读完整文件。
- UI 读取不受模型的 2,000 行 `read_output` 限制或工具输出 token/字符预算约束；继续受实际保留内容边界约束。
- 展示、选择复制和“复制全部”使用同一份可读文本规则：处理 ANSI 控制序列、回车覆盖、UTF-8 跨块边界及无效字节，保留真实内容和顺序。

### 5.3 大日志和选择

完整查看必须包含大日志路径，不能先把 64 MiB 文本同步塞进一个文本控件。

- 建立增量行索引，以分页缓存和虚拟列表绘制可见行；滚动自动读取所需页面，不增加人工“下一页”流程。
- 缓存按文档共享，保留可见区域及邻近页面，离开对话时释放；不为每张卡片复制一份全文。
- 超长单行也要按可见范围处理，避免一条 64 MiB 单行绕过行数优化。横向滚动和复制仍能访问全部保留内容。
- 选择范围基于文档逻辑位置保存，不依赖当前挂载了哪些行；跨页拖选和复制必须读取选区对应的文档内容。
- “复制全部”在后台准备一个一致的输出快照，再在 UI 线程写入剪贴板；失败时不能把预览冒充全文，也不覆盖原剪贴板。
- 运行中、读取中和复制中使用对话/输出身份及请求代次校验；取消后不更新失效界面，不在用户切换对话后突然写剪贴板。

### 5.4 兼容边界

优先不修改数据库 schema：输出 ID 已保存在日志，完整正文保存在输出文件。扩展 UI 投影和运行态状态即可；如需补充文件元数据，单独兼容旧文件。

模型收到的 `LoggedResult.inline`、`wire_text`、`read_output` / `stop_task` 协议保持原行为。只在 UI 层去掉内部说明，不删除模型继续定位输出所需的引用。

## 7. 验收清单

### 自动化：验证用户行为和数据正确性

- 1.7 KB 样例：界面/复制不出现应用添加的 UUID 包装；日志正文和报错不丢失。
- 大于模型内联预算的输出：折叠只显示预览，展开能读到中间和末尾的唯一标记；复制与完整可读输出一致。
- 预览不足 8 行但有更多正文时，仍有展开入口。
- stdout/stderr 交错、ANSI、CR 覆盖、UTF-8 跨块、无效字节、空输出、无末尾换行和超长单行。
- 运行中增量、前台转后台、结束线性化、首尾保留日志：顺序正确、来源完整性正确，缺口不会被标成普通折叠。
- 丢失、权限错误、损坏元数据、旧记录无 ID 和旧文件无元数据：可读预览保留，操作标签诚实。
- 多任务/多子代理/历史对话身份隔离；读取期间切换或删除对话、重试代次、复制完成前取消。
- 展开、收起、复制不改变对话日志、不调用 provider、不改变 token 使用量；纯读取不执行任何命令。
- 命令原本打印的“输出 id …”或 UUID 不被误删。
- 完整复制与选区复制覆盖未渲染/未缓存的中间页面；失败时保留原剪贴板。

### 原型与原生交互

新增或扩展少量受影响场景：短输出、长输出折叠/展开、运行中、历史、已清理/已截断、子代理命令输出。全部检查亮暗主题、完整窗口比例和圆角。

使用临时数据目录和无 I/O 的原型 fixture：

- 点击展开/收起，滚到中部和末尾并核对标记。
- 拖选超过视口边缘、跨分页、横向滚动和复制。
- 分别验证“复制命令”“复制全部”“复制当前输出”“复制预览”。
- 新输出到来时，底部跟随和向上阅读不被打断。
- 10 MiB 多行、接近 64 MiB 保留边界、超长单行样例，确认输入、关闭和停止操作仍响应；记录耗时与内存，不做全量场景截图。
- 复制测试保存并恢复剪贴板所有已有格式；使用应用内 debug 输入事件，不向其他应用发送系统按键。

回归场景选择已有审批卡片、普通 AI 回复、子代理报告、上下文浮层和设置页。只比较应保持原样的场景；输出卡片的预期变化单独审阅。

### 构建和发布前检查

- `cargo clippy --workspace --all-targets --offline -- -D warnings`
- `cargo test -p shellmate-core -p shellmate-ai -p shellmate-store -p shellmate --offline`
- `cargo build -p shellmate --offline`
- `git diff --check`，仅格式化本次改动且原本格式检查通过的文件。

使用现有共享 target，不新增 target 目录、不执行 `cargo clean`。测试使用临时文件、假模型和本地 fixture；不访问真实 SSH、模型服务、用户数据库或钥匙串。根据失败或新增变更补测，已通过的检查不无故重复。

## 8. 完成标准

用户无需理解 UUID 或调用 AI，就能从当前卡片和历史记录查看、选择并复制全部保留输出。阅读长日志不阻塞界面，不打断正在执行的任务。普通命令和子代理命令行为一致；已清理或已丢弃内容的限制清楚可见。只有这些条件和上述验证完成后，才将本计划标为已实施。


## 9. 实施结果（2026-11-25）

M1–M4 已完成：

- 新的本地快照接口对活动日志加一致性锁，支持环形首尾重建、完整性元数据和连续日志增量读取；读取界面不经过模型工具。
- 输出文档在后台流式清理并保存为临时文件，使用稀疏行/列索引和最多 8 个可见页缓存。文本绘制仅处理可见行和可见列，选区映射到实际字形与文档字节。
- 普通步骤、活动命令、后台任务入口、子代理执行记录、历史对话使用同一组件；命令复制和输出复制分开。工具读取通知也不再暴露输出编号。
- 完整复制、当前快照复制、预览复制的标签按内容可用性区分。原日志打印的 UUID、路径和类似提示文本保留。
